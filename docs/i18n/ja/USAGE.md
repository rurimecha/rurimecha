# Rurimecha ユーザーマニュアル

**まず試したい方へ：** [デモ](https://asmr.rurimecha.top/)を開き、ログイン画面でゲスト体験を選ぶと作品を閲覧・再生できます。ゲストの保存と再生位置は記録されません。Ruri は音声作品を提供しません。自分で用意したメディアフォルダーを追加してください。

**使い方を選ぶ：** Windows は MSI インストーラーで導入でき、コマンド入力は不要です。Linux・Docker は以下の手順を参照してください。Android は起動中の Ruri サーバーに接続します。組み込み管理者はライセンスなしで Web と WebDAV を使えます。Android のオンライン再生・ダウンロード、お気に入りクリップには有効なサーバーライセンスが必要です。ダウンロード完了後はスマートフォンでオフライン再生できます。

**料金について：** テスト期間中は無料です。将来の料金は月額 10 元・年額 60 元・永久ライセンス 90 元を予定し、3 台のサーバーに紐付けられ、Android などのクライアントは別枠を消費しません。最終的な内容は正式発表をご確認ください。既存の無料機能を有料にはしません。現在の無料テストライセンスは申請・審査が必要で、発行後 7 日以内に初回有効化し、有効化後 31 日間利用できます。

## インストールと初回ログイン

[リリースページ](https://github.com/rurimecha/rurimecha/releases)から対応するパッケージを取得し、SHA-256 を確認してください。サーバーは Linux x86-64、Docker Linux x86-64、Windows x64 に対応します。Android は別途 APK をインストールし、起動中の Ruri サーバーに接続します。自分の PC をサーバーにする場合はその PC で開き、NAS や別の PC の場合はその端末の LAN アドレスを使います。

### Windows へのインストール

1. `.msi` を開き、「下一步」でインストール先を選びます。現在の Windows ユーザー専用で管理者権限は不要です。標準の場所は `%LOCALAPPDATA%\Programs\Rurimecha` で、スタートメニューもそのユーザー専用です。ほかのユーザーは個別にインストールします。旧 EXE 版がある場合は先に Windows の設定からアンインストールしてください。ライブラリ情報は保持されます。
2. 待ち受け IP とポートを設定し、利用可能か確認します。初期値 `0.0.0.0`、`8080` はすべての IPv4 アドレスで接続を受け付けます。この PC だけで使う場合は `127.0.0.1` を指定します。個別の IP は PC が持つアドレスを指定し、ポートが使用中なら解放するか変更してください。更新・再インストールでは元の設定を標準で引き継ぎます。
3. 完了後、スタートメニューから **Rurimecha** を開きます。必要なら Microsoft の [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) をインストールして開き直してください。
4. 「Ruri → データフォルダーを開く」で `setup-code` をメモ帳で開き、設定コードをコピーして初回設定を行います。

× は通知領域に隠すだけで、Ruri は動き続けます。アイコンをダブルクリックすると再表示し、完全に終了する場合や更新時は右クリックして「Ruri を終了」を選びます。データは `%LOCALAPPDATA%\Rurimecha\data` にあり、プログラムのインストール先とは別です。ほかの端末からの接続は「接続とネットワーク」を参照してください。

### Linux へのインストール

x86-64 サーバーパッケージをすべて展開し、その場所で実行します。

```sh
sudo ./install.sh
```

待ち受け IP とポートを入力し、Enter で `0.0.0.0:8080` を使います。確認に失敗しても元のネットワーク設定は上書きしません。起動と自動起動を設定するので、別の PC から `http://サーバーのLANアドレス:8080/` を開けます。サーバーの GUI は不要です。設定コードは以下で取得します。

```sh
sudo journalctl -u rurimecha.service -g 'Ruri administrator setup code:' -n 1 --no-pager
```

サービスには systemd、同梱メディアツールには glibc 2.35 以降（Ubuntu 22.04、Debian 12 など）が必要です。データは `/var/lib/rurimecha` に保存します。実行ユーザー `rurimecha` にメディアフォルダーと親フォルダーの読み取り権限を与えてください。ディスク全体を全員書き込み可能にする必要はありません。

アドレスを指定してインストールする例：

```sh
sudo ./install.sh --listen-ip 192.168.1.20 --listen-port 18080
```

実際に持つ IP を指定します。`0.0.0.0` はすべての IPv4、`127.0.0.1` はローカル専用です。非対話の新規インストールは初期値を使い、既存環境は引数を指定しなければ元の設定を保持します。対話式の更新でも保持を選べます。

サービスを使わない場合は `./rurimecha-core -data-dir ./data` を実行し、端末を開いたままにします。コードは端末に表示されます。更新時も同じデータフォルダーを指定してください。

### Docker へのインストール

Docker と Docker Compose のある x86-64 Linux PC・NAS を使います。ARM ではこのイメージを直接実行できません。NAS のコンテナー画面でも同じイメージ、マウント、ポートを指定できます。

1. [compose.yaml](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/compose.yaml) と [reset-admin-password.sh](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/reset-admin-password.sh) を同じフォルダーに保存し、隣に `.env` を作ります。

```dotenv
RURI_IMAGE=docker.io/rurimecha/rurimecha:VERSION
RURI_MEDIA_DIR="/srv/media/ASMR"
```

`VERSION` をリリースのバージョンに置き換えます。最新の正式版を追う場合は `latest` を使えます。メディアはホスト上に存在するフォルダーを指定します。Docker Desktop の Linux コンテナーなら `D:/ASMR` のように指定し、ドライブへのアクセスを許可してください。Ruri 内ではホストのパスではなく `/media/library` を追加します。サンプルは読み取り専用で、台本は「Ruri に保存」を選べます。

2. 起動し、ログの `Ruri administrator setup code:` の行からコードを取得します。

```sh
docker compose up -d
docker compose logs core
```

Docker ホストで `http://127.0.0.1:8080/` を開きます。スマートフォンの `127.0.0.1` はスマートフォン自身です。

3. LAN の端末にも公開する場合は、まず Ruri のネットワーク設定で現在の LAN 範囲を保持し、家庭内の範囲を追加します。例：`192.168.1.x`、マスク `255.255.255.0` なら `192.168.1.0/24`。Docker の自動判定に家庭内 LAN が含まれない場合があります。待ち受けは全 IPv4 のままにし、コンテナーが持たないホスト IP を指定しないでください。次に Compose のポートを変更します。

```yaml
ports:
  - "192.168.1.20:18080:8080"
```

`docker compose up -d` を実行し、`http://192.168.1.20:18080/` で接続します。以前の localhost の入口は使えません。実際のホスト IP に置き換え、ファイアウォールで許可してください。意味は **ホストのアドレス : 外部ポート : Ruri 内部ポート** です。

| 指定 | 接続先 | 用途 |
| --- | --- | --- |
| `127.0.0.1:8080:8080` | ホストで `http://127.0.0.1:8080/` | ローカル・同じホストの Nginx |
| `192.168.1.20:18080:8080` | `http://192.168.1.20:18080/` | LAN のほかの端末 |
| `8080:8080` | ホストの全アドレスの 8080 | 自分でアクセスを制限 |

外部ポートだけ変える場合は中央だけ変更し、最後の `8080` は維持します。`docker compose ps` で確認できます。[Docker の説明](https://docs.docker.com/engine/network/port-publishing/)も参照してください。スマートフォンには `172.x.x.x` のコンテナー IP ではなくホストの LAN IP と外部ポートを入力します。自動検出が Docker の外に届かない場合は直接入力してください。

4. Android オンライン再生、追加アカウント、お気に入りクリップにはライセンスとホスト識別子が必要です。Linux の `/etc/machine-id` が空でないことを確認し、既存の `core` の volumes に追記します。

```yaml
volumes:
  - ruri-data:/data
  - ${RURI_MEDIA_DIR}:/media/library:ro
  - /etc/machine-id:/run/ruri-host/machine-id:ro
```

末尾のトップレベル `volumes: ruri-data:` は保持します。別のマシンの識別子をコピーしないでください。`docker compose up -d` 後にサーバーライセンスを有効化します。Windows Docker Desktop では Compose フォルダーの PowerShell で以下を実行します。

```powershell
(Get-CimInstance Win32_ComputerSystemProduct).UUID | Set-Content -Encoding ascii ./ruri-host-id
```

最後のマウントを `./ruri-host-id:/run/ruri-host/machine-id:ro` に置き換えます。コンテナー再作成でもファイルを保持し、別マシンへ移す際は解除・再有効化してください。識別子がなくても管理者の Web 画面と WebDAV は使えます。

アカウント、情報、設定、ライセンスは `ruri-data` にあります。**更新ではボリュームを保持し、`docker compose down -v` を実行しないでください。** 元のメディアはホスト側にあり、別々にバックアップ・移動します。

### 管理者パスワードの初回設定

設定コードと、新しいパスワードを 2 回入力します。その後は `admin` と新しいパスワードでログインします。コードは 1 回限りで、継続利用するパスワードではありません。既存環境は元のアカウントを使います。忘れた場合もデータやボリュームを消さず、下記のリセット手順に従ってください。

自分のパスワードは「アカウントとセッション → パスワード変更」で現在のパスワードと新しいものを 2 回入力します。管理者がユーザーを作成・リセットする場合も 2 回入力します。

## 既存環境の更新

- Linux サービスは新版の展開先で `sudo ./install.sh` を実行します。`/var/lib/rurimecha` を保持して再起動します。手動起動は停止後、新版を元の `-data-dir` で起動します。
- Docker は元の `.env` の `RURI_IMAGE` を更新し、`docker compose pull core`、`docker compose up -d core` を実行します。データボリュームとメディアのマウントは保持します。
- Windows は「Ruri → 更新を確認」から取得・インストールし、開き直します。

対応するデータベースは起動時に更新します。事前にデータフォルダーへ `core.db.before-v…` のバックアップフォルダーを作成します。元のアカウントで利用を続けてください。起動に失敗した場合はデータを保持し、空き容量、書き込み権限、表示されたバージョンの案内を確認して再試行します。

## Windows でのアンインストール

通知領域から Ruri を終了し、Windows の「インストールされているアプリ」で削除します。標準ではデータを保持し、再インストールで再利用できます。

「同时清除本机 Ruri 应用数据」を選ぶと `%LOCALAPPDATA%\Rurimecha\data` のアカウント、ライブラリ情報、コレクション、再生位置、Ruri 内の台本、設定、ローカルライセンスを完全に削除します。ソースフォルダーの元メディアは保持します。必要な情報は移行パッケージに出力し、ライセンスを移す場合は先に解除してください。更新ではこの削除を行いません。リンクや使用中のデータは削除できません。終了してパスを確認し、リンク先のメディアを削除しないでください。

## メディアフォルダーの追加

管理者で「メディアパスを追加」し、サーバー上のフォルダーを選びます。Windows デスクトップ版はシステムの選択画面を開きます。ブラウザーではドライブを選ぶか `C:\Music` などを入力し、Docker では `/media/library` を使います。

自動スキャンはファイルの発見、自動整理は作品への整理、メタデータ取得は RJ 作品の情報取得、メディア情報の抽出は長さやトラックの取得です。個別に有効化でき、ソースから元のフォルダーを、ライブラリから整理した作品を開けます。進行状況はバックグラウンドタスクで確認します。

「フォルダー操作 → 自動処理」で変更できます。スキャンをオフにしても手動実行や既存結果の利用は可能です。整理には完全なスキャン、長さの取得にはファイルの発見が必要です。ソースの削除ではライブラリ情報、手動整理、関連する保存項目を消しますが、元ファイルは保持します。メディアはマウント済みディスクやネットワークにも置けますが、アプリデータはローカルディスクを推奨します。

kikoeru 互換ライブラリはソース種別とアドレスを指定し、作品を選んで追加します。必要ならサーバーの保存先を指定してファイルを保存できます。右上の検索で作品を探し、スマートフォンでは検索を展開して送信します。サークル・タグ・声優タブでは名前で項目を絞り、開いて作品を表示し、戻って続きを閲覧できます。

互換ソースのフォルダーとメディア情報は作品追加時に取得します。「再整理」で更新でき、別途スキャン・抽出は不要です。「通常のフォルダー」の指定は「自動判定を復元」まで保持します。独立作品・通常フォルダーに変更した後は再整理と自動更新を待ち、必要ならタスクを確認します。別画面から戻るとソース一覧から始まります。一時検索・絞り込みは今回のみで、再利用にはフィルターを保存します。

## 作品の検索とバージョンの選択

タイトル、声優、サークル、RJ 番号で検索します。`RJ12` のような前方一致も可能で、2 文字以上入力して待つと候補が表示されます。同じ番号のコピーはソース・パスで区別します。Enter または検索で全結果を表示し、タイトルのみの検索では保存した全言語のタイトルを対象にします。画面を離れると検索・絞り込みは解除し、作品種別、並び順、表示方法は保持します。

カードのタグは 2 行で、残りは「すべてのタグ」から確認します。不明なサークル・声優・タグは代替表示になり、タグ 0 件の操作は無効です。作者は声優として表示し、同じ幅のカードは高さを揃えます。

関連する原作と言語版は一つの入口にまとまります。「ほかの商品バージョンを表示」からソース・パスでサーバーコピーを選び、再生、ファイル表示、管理者による編集ができます。商品版と情報の言語は別々に選べるので、日本語音声を聴きながら別言語の紹介を読めます。商品情報のみの版には再生用ファイルがありません。

「外観と閲覧設定」で原作優先・言語順を選び、作品詳細で個別優先または全体設定への復帰を指定できます。完全な番号検索、ファイル、履歴からは選んだ対象を開き、別バージョンの情報を見ても再生は切り替わりません。

## 作品情報の取得と編集

### DLsite から取得

メタデータ設定で作品情報の取得を有効にし、DLsite 接続をテストします。RJ 番号のある音声作品のタイトル、カバー、紹介を取得できます。

### 言語の表示・編集・更新

新規環境は簡体字中国語と日本語を標準で取得します。繁体字中国語・英語は設定で追加し、提供元が対応する範囲で取得します。

- 情報表示の言語を選ぶと、タイトル、紹介、人物、タグ、価格、画像をまとめて切り替えます。不足する項目は未提供と表示します。
- 編集では対象の言語を選んで保存し、その言語だけ変更します。
- 言語不明の情報は言語を指定できます。既存情報へのマージは不足分のみ、上書きはその言語全体を置き換えます。
- 一言語だけ更新する場合は個別更新から商品情報の強制再取得と言語を選びます。ほかの言語は保持し、失敗分は結果から再試行できます。
- 同じメニューから画像の補完・再取得、メディア情報取得、スキャン、再整理もできます。

タイトル、パス、情報、メッセージは選択して Ctrl+C（macOS は Command+C）、モバイルでは長押しでコピーできます。

## コレクションとプレイリスト

作品メニューから既存または新規コレクションに作品全体を追加します。ライブラリ同様にカード・一覧で閲覧し、詳細・ファイルを開けます。情報が更新されると参照先の最新情報を表示します。

個別の音声・動画・クリップはコレクションの「音の小箱」に入り、作品風のカバーカードで表示します。開いて閲覧、再生、キューやプレイリストへの追加ができます。取り除いても元ファイルと作品への所属は保持します。

スマート発見も作品と音の小箱で表示し、ライブラリの整理に応じて更新します。「コレクションとして保存」で現在の収録範囲を編集可能なものとして保存できます。参照した作品は引き続き更新されます。一部のみ収録と表示された場合、保存対象もその範囲です。

具体的な曲、範囲、重複、順序の保存にはプレイリストを使います。キューから保存でき、コレクションへの収録は作品と個別メディアをまとめます。旧版の自作コレクションは更新時にプレイリストへ移り、多い場合は順番に分割します。曲が未保存の作品は更新時の内容で展開し、復元できない項目は説明を、見つからない保存済みファイルは利用不可と表示します。

プレイリストを開き、「すべて再生」を押すと先頭から再生します。音声または動画の項目をタップすると、その項目からリスト全体の順番どおりに再生し、前の項目には「前へ」で戻れます。「その他の再生方法」から全件のシャッフル再生やキューへの追加ができます。検索後は検索結果のみを再生することもできます。検索結果を直接タップした場合は、リスト全体をその項目から再生します。

項目のメニューでは、その項目だけの再生、次の再生、キューへの追加、ファイル・作品の詳細表示ができます。「ここからキューに追加…」では、その項目以降を次またはキューの最後に追加できます。グループの見出しは展開に使い、グループの再生はメニューから選びます。利用できない項目はタップしても再生できません。プレイリストの編集は現在のキューを変更しません。

## 再生と続きからの再生

作品やフォルダーから再生し、効果音や WAV など利用可能な版・形式を選びます。履歴から続きを開き、よく聴くものをキュー、プレイリスト、コレクションに追加できます。

音声ページ、下部の操作、台本ウィンドウ、ローカル再生には 10 秒戻る・進むがあります。一時停止中の移動では停止を保ちます。長さ未取得・読み込み中はお待ちください。バーをドラッグすると移動先と利用可能な画像を表示します。再生オプションで字幕、音声トラック、チャプターを選び、不足時はメディア情報を取得してください。

時間付き台本は現在の行を表示します。縦画面では横ハンドルをドラッグして大きさを変更し、タップで一行・複数行を切り替えます。横画面では縦ハンドルで幅を変え、タップで隠します。大きな Web 画面では右下に台本が開き、上のハンドルで高さ調整・非表示にできます。下部の台本ボタンで再表示し、閲覧中も維持します。時刻の調整や、カバーと台本を表示する全再生画面への移動も可能です。

Android の時間付き台本で「フローティング字幕」を選び、ほかのアプリ上への表示を許可して戻り、もう一度押します。上下ドラッグで移動、× で閉じます。動画の全画面では Web の Space で停止・再開、矢印で移動、Esc で戻ります。Android はタップで操作、左右のダブルタップで 10 秒移動します。寝る前はスリープタイマーを利用できます。

管理者は台本メニューから作成・編集・形式変換し、プレビューして保存できます。読み取り専用フォルダーなら Ruri 内に保存し、メディアの隣に置く場合は書き込み権限を確認します。変換後は時刻とスタイルを確認してください。

### メディアツールの準備

Linux・Windows・Docker のリリースには FFmpeg と FFprobe を同梱します。対応するローカルファイルの変換、音量正規化、プレビュー、音声トラック、内蔵字幕に利用でき、形式と取得済み情報によって利用可否が異なります。読み取り可能な互換ソースの動画も、対応する画質で変換再生できます。Linux は全体を展開し、`media-tools` をプログラムの隣に置いてください。

管理画面の解析ツールで確認します。独自ツールは `fd` 入力対応版を用意し、両方のフルパスを指定してテスト後に保存します。空にして保存すると標準に戻ります。自動取得にはサーバーのインターネット接続と約 500 MB の空きが必要です。

### ほかのプレーヤー・ファイル管理アプリから接続

WebDAV 接続を作り、`http://サーバー:ポート/dav/` または `https://証明書のサーバー名:ポート/dav/`、現在の Ruri のユーザー名・パスワードを指定します。設定コードは使わず、`/dav/` を二重に付けないでください。例：`http://192.168.1.20:18080/dav/`、Nginx 経由なら `https://ruri.example.com/dav/`。未有効化の場合は組み込み管理者のみ利用できます。

フォルダーから元ファイルを再生できます。読み取り専用で、アップロード、削除、改名、変換、ほかのプレーヤーとの再生位置同期はできません。新規ファイルは Ruri でスキャン後に表示し、再生形式は利用アプリに依存します。

Windows エクスプローラーは「PC → ネットワークの場所を追加」でカスタムの場所と完全な URL、認証情報を入力します。ブラウザーやアドレス欄への貼り付けだけでは場所は登録されません。

Windows WebClient は標準で HTTPS 以外のパスワード認証を拒否します。HTTP でパスワードが繰り返し求められる、名前がない、エラー 67 などはこの制限の可能性があります。HTTP 対応クライアントか、正しい名前と信頼済み証明書の HTTPS を使用してください。ブラウザーの警告を無視しても Windows の信頼は設定されません。

信頼できる家庭内 LAN に限り HTTP 認証を許可する場合、`services.msc` で WebClient を確認し、管理者 PowerShell で実行します。

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\WebClient\Parameters' -Name BasicAuthLevel -PropertyType DWord -Value 2 -Force
Restart-Service WebClient
```

この変更は Windows 全体の WebDAV に適用され、HTTP のパスワードは暗号化されません。再起動で既存接続は切れます。HTTPS 専用へ戻すには `-Value 1` で実行します。サービスがない・組織の制限がある場合は専用クライアントを使ってください。[Microsoft の説明](https://learn.microsoft.com/en-us/iis/publish/using-webdav/using-the-webdav-redirector)も参照できます。

| 症状 | 対処 |
| --- | --- |
| Web 画面も開かない | アドレス、Docker 外部ポート、ファイアウォール、LAN 範囲を確認 |
| パスワード変更後に失敗 | 切断し、資格情報マネージャーの Windows 資格情報から旧記録を消して再接続 |
| ブラウザーで `/dav/` が未対応メソッド | WebDAV クライアントに登録する。Web 用の一覧ページではありません |
| 大きなファイルが失敗、`0x800700DF` | HTTPS でも WebClient の単一ファイル制限があります。専用アプリか Microsoft の `FileSizeLimitInBytes` を確認 |
| 大量のファイルがあるフォルダーのみ失敗 | WebClient のプロパティ容量制限があります。メディアを移さず別アプリを利用 |
| 削除・アップロード・改名不可 | 読み取り専用の仕様です |

## お気に入りクリップ

王冠はライセンス機能の印です。再生可能で長さを取得済みのファイルを開き、必要なら管理者に有効化・更新を依頼します。再生中または動画全画面のオプションからクリップを選び、二つのハンドルで範囲を指定します。標準は現在位置から 30 秒、末尾近くは最後の 30 秒です。拡大して細かく調整できます。試聴は終了位置で停止し、保存・取り消し後は元の位置に戻れます。

アカウントメニューから再生、キュー、プレイリスト、コレクションへの追加や範囲編集ができます。削除で一覧内の参照も消えますが元メディアは保持します。ファイルがない・ライセンス期限切れでもクリップは保持され、復旧・更新後に使えます。

## Android で聴く

アプリを別途インストールし、LAN 検出またはアドレス入力で接続してログインします。検出できなければ同じ LAN と検出設定を確認してください。オンライン再生には有効化済みのサーバーが必要です。

再生前でも「マイ → 再生設定」でソースへの直接接続を切り替えられます。オンはスマートフォンから接続し、サーバーのプロキシが必要・直接再生できない場合はオフにします。再生詳細からも設定できます。

### 保存してオフラインで聴く

1. 作品で版・形式を選び、「端末にダウンロード」でファイルを選択します。ファイルメニューから単体も保存できます。ダウンロード時はログインと有効なライセンスが必要です。
2. 接続・ログイン画面やアカウントメニューのローカルライブラリで進行、一時停止、再開、キャンセルを操作します。キャンセルしても完成分は保持し、失敗した画像・字幕は補完できます。
3. 完了後は通信、ログイン、有効なライセンスがなくてもローカルで聴けます。オンライン詳細のローカル版からも開けます。

元ファイル、保存済みの文章、カバー、利用可能なテキスト字幕を保存します。端末が元形式に対応しない場合は別形式を取得してください。標準は Wi-Fi・有線のみで、制限解除ではモバイル通信を使う場合があります。一度に 500 ファイル、最大 500 版です。

ローカルはバックグラウンド、通知、リピート、シャッフル、タイマー、台本、全画面動画に対応します。キュー、お気に入り、位置は端末に別保存し、復元キューは停止状態で開きます。情報の更新は元サーバー・アカウント・有効なライセンスが必要で、文章、カバー、字幕のみ更新します。ローカル版削除は端末のコピーのみです。ログアウト・サーバー変更では保持し、アンインストール・データ消去で削除されます。機種変更後は再取得が必要です。クリップはサーバー接続時に再生できます。

## プライバシーモードと再生履歴

画面やプレーヤーの目のボタンでカバー、画像、動画を隠し、タイトル、タグ、ファイル名、字幕を伏せ字にします。小さい目で 3 秒だけ確認できます。ナビゲーションやバーは利用でき、設定は端末に保存します。

Android ではこのモードのスピーカー再生前に確認します。ヘッドホン・Bluetooth 切断で停止し、再接続後は手動で再開します。通知やメディアキーで確認が必要ならアプリを開きます。ロック画面・通知の文章とカバーも隠します。

再生位置は引き続き保存します。履歴から個別削除・全削除すると位置と完了状態も消します。コレクション、プレイリスト、クリップ、メディアは保持します。再生中の履歴を消しても聴き続けられ、選び直すと再び記録します。

## サーバーライセンスとアカウント

未有効化・期限切れでも組み込み管理者は Web と WebDAV を利用できます。追加アカウント、公式 Android のオンライン再生、クリップにはサーバーライセンスでキーとサーバー名を入力して有効化してください。

有効化後はユーザー管理でアカウントを作成できます。同じライブラリを使い、コレクション、プレイリスト、設定、位置、クリップは個別です。アクセス権で無効化すると全セッションと WebDAV を終了します。パスワード、役割、ライセンスが変わった場合は案内に従い再ログインします。

有効化・更新・解除にはサーバーのネット接続が必要で、有効期間内はオフラインでも使えます。延長後は同じキーで更新します。サーバー変更は旧側で解除してから新側で有効化します。旧サーバーが動かない場合は購入情報を添えて提供者に連絡します。同じマシンでコンテナーを再作成する場合はデータとホスト識別子を保持してください。

「アカウントとセッション → ログインセッションと WebDAV」で端末名、種類、ログイン IP、日時・期限を確認し、不要なログインを解除できます。IP はログイン時のもので、後のネット変更は追いません。ブラウザーは種類と OS、Android は機種、デスクトップは PC 名を表示します。終了・期限切れの履歴はここには保持しません。

## 接続とネットワーク

### ほかの端末から接続

Linux は標準で `http://サーバーLANアドレス:8080/` に接続できます。ファイアウォールを確認してください。Windows はインストール時の設定（初期値は全 IPv4 の 8080）を使い、インストール先の `rurimecha-core.exe` をプライベートネットワークで許可します。`127.0.0.1` だけなら、それを保持して LAN の待ち受けを追加してください。スリープ、電源オフ、終了中はほかの端末から再生できません。Docker はホスト IP と外部ポートを使います。

LAN 範囲が空なら直接つながるプライベート範囲を判定します。手動は `192.168.1.0/24` のように 1 行一つで、Docker・VPN・別範囲を追加するときは現在の値も保持します。外部接続はサーバー全体とアカウント両方のリモート許可が必要です。HTTP のログイン・メディアは暗号化されないため、外では HTTPS または信頼できる VPN を使います。

### HTTPS の有効化

HTTP を保持するか、HTTPS も異なるポートで有効にします（初期値 `8443`）。PEM 証明書と対応する未暗号化の秘密鍵を指定し、交換時は両方選び直します。証明書に含まれる名前・IP で接続し、端末で信頼してください。HTTP で送る場合は信頼できる LAN 内で行います。強制 HTTPS では HTTP を転送しますが、プレーヤー・WebDAV は HTTPS を直接指定してください。変更は切断を伴うため新アドレスを控えます。

Docker は `"192.168.1.20:8443:8443"` などのマッピング追加後に `docker compose up -d` を行います。転送を使う場合は HTTPS の内外ポートを合わせてください。Nginx を使う場合は次の手順に従います。

## Nginx 経由の接続

Nginx、ドメイン、証明書のある方向けです。家庭内だけなら直接接続できます。Nginx で HTTPS を提供し、Ruri へ HTTP で接続できます。同じ証明書を Ruri にも登録する必要はありません。同一ホストの Nginx は標準 Docker ブリッジを含め信頼するプロキシの入力不要で、訪問者 IP で権限を判断します。専用ドメインのルート `https://ruri.example.com/` を使い、`/ruri/` のようなサブパスには対応しません。HTTP は信頼できる経路で、HTTPS 上流では証明書検証を設定します。

### 例：同一ホストの Nginx で HTTPS

1. ドメインを Nginx に向け、端末が信頼する一致した証明書を用意します。例は `/etc/nginx/certs/ruri-fullchain.pem` と `/etc/nginx/certs/ruri-key.pem` です。
2. 同じホストなら信頼するプロキシは空のままです。Nginx 専用なら Ruri を `127.0.0.1:8080` にし、LAN 範囲は現在の値に家庭内範囲 `192.168.1.0/24` などを追加します。
3. Debian/Ubuntu では `/etc/nginx/conf.d/ruri.conf` を作り、ドメイン・パスを置き換えます。

```nginx
server {
    listen 80;
    server_name ruri.example.com;
    return 308 https://ruri.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name ruri.example.com;
    ssl_certificate     /etc/nginx/certs/ruri-fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/ruri-key.pem;

    client_max_body_size 257m;
    client_body_timeout 600s;
    send_timeout 600s;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header Connection "";

        proxy_buffering off;
        proxy_request_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_redirect off;
        gzip off;
    }
}
```

4. `sudo nginx -t`、`sudo systemctl reload nginx` を実行します。
5. `https://ruri.example.com/` でログイン、設定保存、再生・移動を確認し、WebDAV は `/dav/`、移行アップロードも同じ入口を使います。

これは利用者から直接受ける一段の Nginx の例です。CDN 等が前にある場合はそこで信頼する入口を限定し、利用者アドレスを復元してください。利用者が自由に送るヘッダーを信用せず、自分のプロキシ・専用範囲だけ信頼します。外部接続には双方のリモート許可が必要です。家庭内専用ならオフのまま、HTTPS server に `allow 192.168.1.0/24; deny all;` を追加できます。信頼できない上流は HTTPS・信頼できるトンネルを使います。

認証情報、Cookie、Origin、Referer を保持し、偽装や不要な書き換えをしないでください。Authorization を占有する Nginx の Basic 認証は競合します。PROPFIND を許可し、メディア、画像、ログイン応答を公開キャッシュしないでください。

### Docker と HTTPS 上流

- Ruri のみ Docker：標準ブリッジと `127.0.0.1:8080:8080` を保持し、ホストの Nginx は `http://127.0.0.1:8080` に接続します。再作成で信頼プロキシの変更は不要です。家庭内 LAN 範囲を設定します。
- 両方 Docker：専用ネットワークと `http://core:8080` を使います。localhost は Nginx 自身です。Nginx の固定 IP または専用範囲のみ信頼し、他ユーザーと共用の範囲は指定しません。Ruri のホストポート公開は不要です。
- HTTPS 上流：Ruri の HTTPS を有効にし、`https://127.0.0.1:8443` または `https://core:8443` と以下を使います。

```nginx
proxy_ssl_server_name on;
proxy_ssl_name ruri.example.com;
proxy_ssl_verify on;
proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
proxy_ssl_verify_depth 3;
```

名前は上流証明書に含まれる必要があります。私設 CA はルート証明書のパスに変え、検証はオフにしないでください。

### よくある問題

| 症状 | 確認 |
| --- | --- |
| ログイン・保存で 403 | LAN・リモート権限、例の設定、別端末・コンテナーのプロキシの信頼アドレス |
| 転送ループ・8443 に移動 | プロキシ設定と信頼。Nginx だけが HTTPS の場合は Ruri の強制転送を解除 |
| 502 | 起動、上流アドレス・ポート、HTTPS の名前・ルート証明書 |
| ページだけ開き再生・移動不可 | Range を保持し、メディアキャッシュ・バッファを無効化して直接再生を確認 |
| 移行アップロード 413 | `client_max_body_size` と Ruri の容量制限 |
| WebDAV 一覧不可 | `/dav/`、認証、PROPFIND |

## 引っ越しと復元

旧サーバーの管理者で移行と復元を開き、全作品情報、システムデータ、両方から選びます。システムにはアカウント、設定、コレクション、位置が含まれ、パスワードが必要です。パッケージとパスワードを保管してください。メディアを別途移し、新サーバーでログイン後、パッケージと新パスを指定して復元をプレビューします。不足を確認して実行します。不足ファイルでも情報や保存項目・位置を保持でき、元の相対位置に置いてスキャンすると再生できます。システム復元後は再起動し、旧アカウントでログインします。

一作品だけなら作品の移行から出力します。相対パスが同じなら移行先の同じ操作で情報と手動整理を置換し、まだないなら全体の移行画面から取り込みます。情報、出典、編集、画像と更新設定を保持します。元メディア、ログ、タスク記録、サーバーライセンス、スマートフォンの保存は別途扱います。

## 管理者パスワードのリセット

- Linux サービスは `sudo /opt/rurimecha/reset-admin-password.sh --service`。実行中なら再起動します。手動環境は停止して展開先で `./reset-admin-password.sh` を実行し、別データパスは引数に追加して再起動します。
- Windows は通知領域から終了し、インストール先（標準 `%LOCALAPPDATA%\Programs\Rurimecha`）の `reset-admin-password.cmd` を実行して開き直します。別データパスならその場所のコマンドプロンプトで `reset-admin-password.cmd "データパス"` を実行します。
- Docker は Compose と同じ場所で `./reset-admin-password.sh` を実行します。起動中なら一時停止して再起動します。

表示されたユーザー名・新パスワードでログインします。名前とデータは保持し、同アカウントの端末は再ログインが必要です。

## ゲスト体験

管理者がユーザー管理で有効にすると、ログイン画面からパスワードなしで閲覧・再生できます。編集、コレクションや位置の保存はできません。無効化で利用を終了し、再有効化後は入り直せます。公開デモは公開再生が許可された専用ライブラリを使ってください。

## 表示言語の選択

接続・ログイン画面やアカウントメニューの言語ボタンで 简体中文、繁體中文、日本語、English、システムに従うを選べます。ログイン後は外観と閲覧設定からも変更でき、アカウントに保存してほかの端末でも使います。未ログインの選択はその端末だけに保存し、ログアウト後に戻ります。ローカルライブラリはオフライン時に直近の言語を使います。

システムに従う場合は対応する端末言語を優先し、繁体字地域は繁体字、ほかの中国語地域は簡体字、対応言語がなければ英語です。作品名、ファイル名、コレクション名、情報・音声・字幕の言語は変えません。それぞれのメニューで選択してください。インストーラーは簡体字中国語、管理・CLI ツールは原則英語、過去のリリースノートは中国語と英語です。


## サークル・声優・イラストレーター

サークル・声優・イラストレーターで名前を検索し、項目を開くとライブラリの作品を表示します。項目の画像には関連作品の表紙を使います。作品を選ぶと詳細を開きます。作品の取得元でDLsiteのフロアを選ぶと、ほかの作品を探してDLsiteを開けます。「作品を探す」では未登録の名前も指定できます。設定済みの互換ソースでも検索できます。名前検索には漏れや同名の参加者が含まれる場合があり、互換ソースでのイラストレーター検索は署名の検索対応に依存します。更新は1ページ目から取得し直します。失敗時は表示中の結果を保持し、再試行できます。作品やメディアは自動追加されません。


## 変更がないときの自動確認

定期確認で変更が見つからなければ、整理、作品情報取得、メディア情報抽出を繰り返しません。既存の保留処理や再試行は引き続き実行します。

## 問題の確認と詳細な診断

管理者は設定からシステムログを開けます。通常は「要確認」で問題を確認し、「すべての記録」で操作結果を表示できます。問題を報告するときは詳細を開いて記録を確認してください。進捗、失敗した項目、再試行方法はタスクの詳細にあります。

調査時は設定の「詳細な診断」を有効にして保存し、問題を再現した後に無効にして保存します。設定はサーバー全体に適用され、再起動後も保持されます。無効化後は新しい診断記録を追加しません。既存の記録は容量制限内で保持され、ログの「診断記録」で確認できます。通常の利用では無効のままで構いません。


## リスニング統計とおすすめ

サイドバーまたはアカウントメニューから「リスニングとおすすめ」を開きます。「リスニング統計」では再生時間、カレンダー、月別の推移、よく聴く作品・声優・サークル・タグを確認できます。過去30日、12か月、年、全期間を選べます。サーバーのライブラリからの再生を記録し、スマートフォンのローカルライブラリは含めません。

作品詳細で「自分の評価」を選び、星1～5つで評価できます。もう一度開くと変更や取り消しができます。評価はアカウントごとに作品全体へ付け、形式や再生グループで共通です。カードには公開評価と自分の評価を分けて表示します。

「あなたへのおすすめ」では、好みに合いそうな作品、いつもと違う作品、久しぶりに聴く作品を選べます。作品詳細を開いたり、直接再生したりできます。「おすすめを入れ替える」で候補を変更します。再生位置の記録を削除しても、統計と評価は残ります。


### 動画の画質と変換制限

動画再生中にプレーヤー設定の「動画の画質」を開きます。変換に対応する動画では解像度とビットレートを選択でき、切り替え後はバッファリングして現在位置から再開します。変換できない動画には元の形式だけを表示します。ローカルソースと読み取り可能な kikoeru 互換ソースの動画に対応します。元の形式を再生できるかは端末によります。互換再生の「自動」は既定の画質予算を使い、回線速度に応じた継続的な自動調整は行いません。

管理者は解析設定で変換後の最大高さ、動画ビットレート、処理ごとの最大ワーカースレッド数を指定できます。高さとビットレートの 0 は制限なしです。スレッド数は 1～64、0 は 1 ワーカーです。制限は新しい変換処理に適用され、元の形式の直接再生には影響しません。元ファイルを保持し、画像を拡大せず元のフレームレートを保ちます。

終了したタスクと実行ログは最大48時間保存されます。終了後の詳細には再試行できる未完了項目を表示し、成功項目は合計に含まれます。記録が消えた後は作品やソースから再実行できます。作品情報、お気に入り、再生位置、字幕の下書きは保持されます。今回の更新では以前のタスク記録を引き継がず、移行成功後に旧データベースのバックアップを削除します。
