# Rurimecha ユーザーマニュアル

**まず試したい方へ：** [デモ](https://asmr.rurimecha.top/)を開き、ログイン画面でゲスト体験を選ぶと作品を閲覧・再生できます。ゲストの保存と再生位置は記録されません。Ruri は音声作品を提供しません。自分で用意したメディアフォルダーを追加してください。

**使い方を選ぶ：** Windows は MSI インストーラーで導入でき、コマンド入力は不要です。Linux・Docker は以下の手順を参照してください。Android では端末内のファイルを整理・再生でき、Ruri サーバーにも接続できます。組み込み管理者は Web、Android、WebDAV からログインできます。お気に入りクリップ、AI、スマート接続にはライセンスが必要です。通常の再生とダウンロードはアカウントの権限に応じて利用できます。追加のアカウントには有効なサーバーライセンスが必要です。

**料金について：** テスト期間中は無料です。将来の料金は月額 10 元・年額 60 元・永久ライセンス 90 元を予定し、3 つのインストールを有効化できる予定です。最終的な内容は正式発表をご確認ください。スマートフォンとサーバーの有料機能は個別に有効化します。公式サイトでご自身のメールアドレスを入力すると、無料テストライセンスが自動送信されます。審査を待つ必要はなく、各アドレスにつき 1 回限りです。発行後 7 日以内に初回有効化し、その後 31 日間利用できます。届かない場合は迷惑メールを確認し、後で再申請するか発行済みライセンスを確認してください。再申請しても期限は延長されません。

## インストールと初回ログイン

[リリースページ](https://github.com/rurimecha/rurimecha/releases)から対応するパッケージを取得し、SHA-256 を確認してください。サーバーは Linux x86-64、Docker Linux x86-64、Windows x64 に対応します。Android は別途 APK をインストールして端末内のファイルを再生するか、起動中の Ruri サーバーに接続します。自分の PC をサーバーにする場合はその PC で開き、NAS や別の PC の場合はその端末の LAN アドレスを使います。

### Windows へのインストール

1. `.msi` を開き、「下一步」でインストール先を選びます。選んだ場所に `Rurimecha` フォルダーを作成します。同名フォルダーを選んだ場合はそのまま使用し、更新時は元の場所を引き継ぎます。現在の Windows ユーザー専用で管理者権限は不要です。標準の場所は `%LOCALAPPDATA%\Programs\Rurimecha` で、スタートメニューもそのユーザー専用です。ほかのユーザーは個別にインストールします。旧 EXE 版がある場合は先に Windows の設定からアンインストールしてください。ライブラリ情報は保持されます。
2. 待ち受け IP とポートを設定し、利用可能か確認します。初期値 `0.0.0.0`、`8080` はすべての IPv4 アドレスで接続を受け付けます。この PC だけで使う場合は `127.0.0.1` を指定します。個別の IP は PC が持つアドレスを指定し、ポートが使用中なら解放するか変更してください。更新・再インストールでは元の設定を標準で引き継ぎます。
3. デスクトップにショートカットを追加するには、インストールオプションで「安装后创建桌面快捷方式」を選びます。新規インストール時はチェックが外れています。必要なら Microsoft の [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) をインストールして開き直してください。
4. スタートメニューから **Rurimecha** を開きます。初回設定ページで `admin` の新しいパスワードを 2 回入力し、「パスワードを設定してログイン」を選びます。

× は通知領域に隠すだけで、Ruri は動き続けます。アイコンをダブルクリックすると再表示し、完全に終了する場合や更新時は右クリックして「Ruri を終了」を選びます。データは `%LOCALAPPDATA%\Rurimecha\data` にあり、プログラムのインストール先とは別です。ほかの端末からの接続は「接続とネットワーク」を参照してください。

### Linux へのインストール

x86-64 サーバーパッケージをすべて展開し、その場所で実行します。

```sh
sudo ./install.sh
```

待ち受け IP とポートを入力し、Enter で `0.0.0.0:8080` を使います。確認に失敗しても元のネットワーク設定は上書きしません。起動と自動起動を設定するので、別の PC から `http://サーバーのLANアドレス:8080/` を開けます。サーバーの GUI は不要です。サーバーで `sudo cat /var/lib/rurimecha/default-admin-password.txt` を実行し、表示された初期管理パスワードを設定ページに入力してから、`admin` の新しいパスワードを 2 回入力します。

サービスには systemd、同梱メディアツールには glibc 2.35 以降（Ubuntu 22.04、Debian 12 など）が必要です。データは `/var/lib/rurimecha` に保存します。実行ユーザー `rurimecha` にメディアフォルダーと親フォルダーの読み取り権限を与えてください。ディスク全体を全員書き込み可能にする必要はありません。

アドレスを指定してインストールする例：

```sh
sudo ./install.sh --listen-ip 192.168.1.20 --listen-port 18080
```

実際に持つ IP を指定します。`0.0.0.0` はすべての IPv4、`127.0.0.1` はローカル専用です。非対話の新規インストールは初期値を使い、既存環境は引数を指定しなければ元の設定を保持します。対話式の更新でも保持を選べます。

サービスを使わない場合は `./rurimecha-core -data-dir ./data` を実行し、端末を開いたままにします。更新時も同じデータフォルダーを指定してください。

### Docker へのインストール

Docker と Docker Compose のある x86-64 Linux PC・NAS を使います。ARM ではこのイメージを直接実行できません。NAS のコンテナー画面でも同じイメージ、マウント、ポートを指定できます。

1. [compose.yaml](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/compose.yaml) と [reset-admin-password.sh](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/reset-admin-password.sh) を同じフォルダーに保存し、隣に `.env` を作ります。

```dotenv
RURI_IMAGE=docker.io/rurimecha/rurimecha:VERSION
RURI_MEDIA_DIR="/srv/media/ASMR"
```

`VERSION` をリリースのバージョンに置き換えます。最新の正式版を追う場合は `latest` を使えます。メディアはホスト上に存在するフォルダーを指定します。Docker Desktop の Linux コンテナーなら `D:/ASMR` のように指定し、ドライブへのアクセスを許可してください。Ruri 内ではホストのパスではなく `/media/library` を追加します。サンプルは読み取り専用で、台本は「Ruri に保存」を選べます。

2. Ruri を起動します。

```sh
docker compose up -d
```

`docker compose exec core cat /data/default-admin-password.txt` で初期管理パスワードを確認します。Docker ホストで `http://127.0.0.1:8080/` を開き、確認したパスワードを入力してから、ご自身の管理者パスワードを設定します。スマートフォンの `127.0.0.1` はスマートフォン自身です。

3. LAN の端末にも公開する場合は、まず Ruri のネットワーク設定で現在の LAN 範囲を保持し、家庭内の範囲を追加します。例：`192.168.1.x`、マスク `255.255.255.0` なら `192.168.1.0/24`。Docker の自動判定に家庭内 LAN が含まれない場合があります。待ち受けは全 IPv4 のままにし、コンテナーが持たないホスト IP を指定しないでください。次に Compose のポートを変更します。

```yaml
ports:
  - "192.168.1.20:18080:8080"
```

`docker compose up -d` を実行し、`http://192.168.1.20:18080/` で接続します。以前の localhost の入口は使えません。実際のホスト IP に置き換え、ファイアウォールで許可してください。意味は **ホストのアドレス : 外部ポート : Ruri 内部ポート** です。

| 指定 | 接続先 | 用途 |
| --- | --- | --- |
| `127.0.0.1:8080:8080` | ホストで `http://127.0.0.1:8080/` | ローカル・同じホストの Nginx |
| `192.168.1.20:18080:8080` | `http://192.168.1.20:18080/` | LAN のほかの端末 |
| `8080:8080` | ホストの全アドレスの 8080 | 自分でアクセスを制限 |

外部ポートだけ変える場合は中央だけ変更し、最後の `8080` は維持します。`docker compose ps` で確認できます。[Docker の説明](https://docs.docker.com/engine/network/port-publishing/)も参照してください。スマートフォンには `172.x.x.x` のコンテナー IP ではなくホストの LAN IP と外部ポートを入力します。自動検出が Docker の外に届かない場合は直接入力してください。

4. お気に入りクリップ、AI、スマート接続にはサーバーライセンスとホスト識別子が必要です。Linux の `/etc/machine-id` が空でないことを確認し、既存の `core` の volumes に追記します。

```yaml
volumes:
  - ruri-data:/data
  - ${RURI_MEDIA_DIR}:/media/library:ro
  - /etc/machine-id:/run/ruri-host/machine-id:ro
```

末尾のトップレベル `volumes: ruri-data:` は保持します。別のマシンの識別子をコピーしないでください。`docker compose up -d` 後にサーバーライセンスを有効化します。Windows Docker Desktop では Compose フォルダーの PowerShell で以下を実行します。

```powershell
(Get-CimInstance Win32_ComputerSystemProduct).UUID | Set-Content -Encoding ascii ./ruri-host-id
```

最後のマウントを `./ruri-host-id:/run/ruri-host/machine-id:ro` に置き換えます。コンテナー再作成でもファイルを保持し、別マシンへ移す際は解除・再有効化してください。識別子がなくても管理者の Web 画面と WebDAV は使えます。

アカウント、情報、設定、ライセンスは `ruri-data` にあります。**更新ではボリュームを保持し、`docker compose down -v` を実行しないでください。** 元のメディアはホスト側にあり、別々にバックアップ・移動します。

### 管理者パスワードの初回設定

新規インストールでは、`admin` 用のパスワードをご自身で設定します。次回からは設定したパスワードでログインしてください。

- **Windows デスクトップ画面**：初期管理パスワードは自動入力されます。新しいパスワードを 2 回入力し、「パスワードを設定してログイン」を選択してください。
- **ブラウザーや Android から新しいサーバーに接続する場合**：サーバーが生成した「初期管理パスワード」を入力してから、ご自身の新しいパスワードを 2 回入力します。ログイン画面にも次の確認方法が表示されます。
  - Windows：Ruri をインストールした PC で「Ruri → 初期管理パスワードを表示」を選択します。保存先は `%LOCALAPPDATA%\Rurimecha\data\default-admin-password.txt` です。
  - Linux サービス：サーバーの端末で `sudo cat /var/lib/rurimecha/default-admin-password.txt` を実行します。
  - Docker Compose：サーバーの Compose フォルダーで `docker compose exec core cat /data/default-admin-password.txt` を実行します。`docker run` の場合は `docker exec <コンテナー名> cat /data/default-admin-password.txt` を実行し、実際の名前に置き換えます。NAS ではコンテナーの端末から `cat /data/default-admin-password.txt` を実行できます。
  - 手動起動・独自のデータフォルダー：起動時に表示される保存先の `default-admin-password.txt` を開きます。

初期管理パスワードは初回設定専用で、ログインには使えません。設定後は無効になり、ファイルが削除されます。他の人に共有しないでください。既存環境は元のアカウントとパスワードを使います。忘れた場合はデータやボリュームを削除せず、下記のリセット手順に従ってください。

自分のパスワードは「アカウントとセッション → パスワード変更」で現在のパスワードと新しいものを 2 回入力します。管理者がユーザーを作成・リセットする場合も 2 回入力します。

## 既存環境の更新

**旧版の Android アプリは新しいサーバーに対応していません。両方を同時に更新してください。**

アカウントメニューの「アカウントとログイン」を開き、「バージョンと更新」で「更新を確認」を選びます。Android でサーバーに接続中は、アプリとサーバーを別々に確認できます。接続画面や端末内ライブラリの設定からもアプリの更新を確認できます。確認できない場合は再試行するか、[公式リリースページ](https://github.com/rurimecha/rurimecha/releases/latest)を開いてください。

正式版は自動または手動で更新を確認するとき、プラットフォーム、バージョン、ランダムに生成したインストール識別番号、ライセンスの状態を Ruri 公式サイトに送信することがあります。Ruri の運営者はこの情報を使ってバージョンごとのインストール数を集計します。

- **Windows デスクトップ**。「バージョンと更新」からダウンロードとインストールを選び、確認後にインストーラーの案内に従います。中止した場合は現在の版を開き直せます。ブラウザーやスマートフォンから接続している場合は、サーバーの PC で更新します。
- **Android**。「ダウンロードしてインストール」を選び、システムのインストール画面で確認します。インストールの許可が求められた場合は端末の案内に従います。中止や失敗の場合は今の版を引き続き使用できます。上書きインストールでは端末内ライブラリ、ライセンス、選択したフォルダーへのアクセス権が保持されます。
- **Linux**。サーバーで公式 x86-64 完全パッケージを展開します。サービスとして使用している場合は新版のフォルダーで `sudo ./install.sh` を実行し、今の待ち受け設定とデータを引き継ぎます。手動で起動している場合は停止後、同じ `-data-dir` で新版を起動します。
- **Docker**。既存の Compose `.env` の `RURI_IMAGE` を `docker.io/rurimecha/rurimecha:<新バージョン>` に変更し、`docker compose pull core` と `docker compose up -d core` を実行します。既存のデータボリュームとメディアのマウントは保持します。独自構成では通常の手順でイメージを置き換えます。

Ruri は起動時に対応するデータベースを自動で更新します。データベースを更新する前に、データフォルダー内の `core.db.before-v…` フォルダーに一時バックアップを作成し、更新が正常に完了すると自動で削除します。更新後は、これまでのアカウントでログインしてください。起動に失敗した場合は、データフォルダーを残し、バックアップフォルダーがあればそれも残してください。空き容量と書き込み権限を確認し、起動時の案内に従ってバージョンを確認してから再試行してください。

## Windows でのアンインストール

通知領域から Ruri を終了し、Windows の「インストールされているアプリ」で削除します。標準ではデータを保持し、再インストールで再利用できます。

「同时清除本机 Ruri 应用数据」を選ぶと `%LOCALAPPDATA%\Rurimecha\data` のアカウント、ライブラリ情報、コレクション、再生位置、Ruri 内の台本、設定、ローカルライセンスを完全に削除します。ソースフォルダーの元メディアは保持します。必要な情報は移行パッケージに出力し、ライセンスを別の端末で使う場合は、「サーバーライセンス」で「紐付けを解除」を選んでからアンインストールしてください。更新ではこの削除を行いません。リンクや使用中のデータは削除できません。終了してパスを確認し、リンク先のメディアを削除しないでください。

データの場所に別のファイルやフォルダーがあると表示された場合は、自分で追加したものを別の場所に移してから再試行するか、データ消去のチェックを外してください。

## メディアフォルダーの追加

管理者でログインし、ホームで「メディアのパスを追加」を選びます。メディアソース画面で「ソースを追加」を選び、「サーバー上のフォルダー」を指定します。Windows デスクトップ版ではパス横のフォルダーアイコンから Windows の選択画面を開けます。ブラウザーではドライブとフォルダーを選ぶか `C:\Music` などを入力します。Docker では `/media/library` を選べます。

自動スキャンはファイルの発見、自動整理は作品への整理、メタデータ取得は RJ 作品の情報取得、メディア情報の抽出は長さやトラックの取得です。個別に有効化でき、ソースから元のフォルダーを、ライブラリから整理した作品を開けます。進行状況はバックグラウンドタスクで確認します。

「フォルダー操作 → 自動処理」で変更できます。スキャンをオフにしても手動実行や既存結果の利用は可能です。整理には完全なスキャン、長さの取得にはファイルの発見が必要です。ソースの削除ではライブラリ情報、手動整理、関連する保存項目を消しますが、元ファイルは保持します。メディアはマウント済みディスクやネットワークにも置けますが、アプリデータはローカルディスクを推奨します。

ディレクトリ画面にはASMR.oneソースが用意されており、URLを入力せずに作品を探してライブラリに追加できます。管理者は名前、プロキシ、ダウンロード先を変更できますが、標準ソースは削除できません。同じURLで追加したソースは別々に保持され、声優画面のASMR.oneへの移動には標準ソースを使用します。作品を追加してもファイルは自動ダウンロードされません。必要なファイルを選んで保存してください。

Windows 版 Ruri と Android の端末内ライブラリでは、オンラインソースの接続に端末のシステムプロキシを使用できます。ソースごとにプロキシを指定するには、そのソースの設定で入力してください。システムプロキシを変更した後は、ディレクトリを更新するか、もう一度お試しください。進行中の再生やダウンロードは現在の接続を使用します。

ディレクトリ画面のソースメニューでサーバーのダウンロード先を設定します。フォルダーボタンでサーバー内を参照するか、パスを入力してください。「書き込みをテスト」で確認でき、保存時にも再確認します。フォルダーがなければ作成します。失敗したら別のフォルダーを選ぶか、Ruri を実行するアカウントに書き込み権限を付けてから保存してください。パスを空にして保存すると、このソースのサーバーダウンロードを解除できます。

kikoeru 互換ライブラリはソース種別とアドレスを指定し、作品を選んで追加します。必要ならサーバーの保存先を指定してファイルを保存できます。右上の検索で作品を探し、スマートフォンでは検索を展開して送信します。サークル・タグ・声優タブでは名前で項目を絞り、開いて作品を表示し、戻って続きを閲覧できます。

作品をライブラリに追加した後、管理者は作品のファイル欄で「作品をサーバーに保存」を選べます。ツリーを開いてフォルダーやファイルを選び、拡張子ボタンで同じ形式をまとめて選択できます。「すべて選択」「選択を解除」も使えます。選択数と合計サイズ、不明なサイズを確認し、「保存開始」を選びます。元の階層を保ってソースのサーバー保存先に保存し、完成済みのファイルはスキップします。画面を閉じても保存は続きます。同じ作品の保存画面を開き直すと進捗確認や停止ができます。失敗や停止の後は元の選択を保ち、未完了のファイルを再試行できます。同時保存は最大 2 タスクです。ファイルの重複や上限に達した場合は後で再試行してください。

作品のファイル欄から「画像の分類」を開くと、プレビュー、用途の変更、表紙の選択ができます。互換ソースの画像にはネットワーク接続が必要です。読み込みに失敗した画像を押すと再試行します。16 MiB を超える画像はプレビューできないため、ファイル一覧からダウンロードして確認してください。

互換ソースのフォルダーとメディア情報は作品追加時に取得します。「再整理」で更新でき、別途スキャン・抽出は不要です。「通常のフォルダー」の指定は「自動判定を復元」まで保持します。独立作品・通常フォルダーに変更した後は再整理と自動更新を待ち、必要ならタスクを確認します。同じソース内でサブフォルダーに入る、上の階層へ戻る、一時的に別画面へ移動する場合、ファイル種類の絞り込みを保持します。「戻る」は以前の閲覧位置へ戻り、絞り込みの変更を一つずつ取り消しません。別のソースを選ぶか別作品のファイルを開くと、種類を既定に戻します。サブフォルダーに入ると名前検索をクリアしますが、ファイル詳細を開いて戻る場合は検索と閲覧位置を保持します。「絞り込みをクリア」で既定に戻せます。前の閲覧画面を復元せずに新しく起動した場合、一時条件は保持しません。再利用する条件はフィルターとして保存してください。

## 作品の検索とバージョンの選択

作品の「収録内容」で、ファイルの種類から「すべてのファイル」を選ぶと、選択中の再生グループ以外も含め、作品内のすべてのファイルを確認できます。「画像」や「台本・文書」を選ぶと、該当する添付ファイルに絞れます。ファイル名を選ぶと、テキストを読んだり、画像を拡大したり、PDF のページをめくったりできます。プレビューの上限はテキスト 2 MiB、画像 16 MiB、PDF 32 MiB です。上限を超えるファイルは別のアプリで開いてください。

タイトル、声優、サークル、RJ 番号で検索します。`RJ12` のような前方一致も可能で、2 文字以上入力して待つと候補が表示されます。同じ番号のコピーはソース・パスで区別します。Enter または検索で全結果を表示し、タイトルのみの検索では保存した全言語のタイトルを対象にします。画面を離れると検索・絞り込みは解除し、作品種別、並び順、表示方法は保持します。

作品カードの「すべてのタグ」で、作品に付いているタグを確認できます。作者は声優の欄に表示されます。

関連する原作と言語版は一つの入口にまとまります。「ほかの商品バージョンを表示」からソース・パスでサーバーコピーを選び、再生、ファイル表示、管理者による編集ができます。商品版と情報の言語は別々に選べるので、日本語音声を聴きながら別言語の紹介を読めます。商品情報のみの版には再生用ファイルがありません。

「外観と閲覧設定」で原作優先・言語順を選び、作品詳細で個別優先または全体設定への復帰を指定できます。完全な番号検索、ファイル、履歴からは選んだ対象を開き、別バージョンの情報を見ても再生は切り替わりません。

## 作品情報の取得と編集

### DLsite から取得

有効なサーバーライセンスがある場合、管理者は「ネットワーク設定」の「スマート接続」を有効にして、DLsite や ASMR Online への別の経路を試せます。アクセスできるかはサーバーのネットワークと地域によって異なります。無効にしても取得済みの資料は保持されます。

Android の端末内ライブラリで「この端末のライセンス」を有効にすると、「作品情報の取得設定」の「スマート接続」をオンにできます。アクセスできるかは端末のネットワークと地域によって異なります。

作品情報を取得する際は、IPv4 で接続できるサイトとプロキシを使用してください。

メタデータ設定で作品情報の取得を有効にし、DLsite 接続をテストします。RJ 番号のある音声作品のタイトル、カバー、紹介を取得できます。

### フォルダー単位の個別更新

管理者はルートフォルダーのカード、現在のフォルダー、サブフォルダーのメニューから個別更新を開けます。作品単位と同じ8操作を利用できます。キャッシュ優先・強制の作品情報更新、画像の補完・再取得、メディア情報の補完・強制取得、ファイルの再スキャン、再整理です。従来のスキャン・再整理メニューも引き続き使えます。

一覧の絞り込み条件に関係なく、対象フォルダーとすべてのサブフォルダーを処理します。情報と画像は登録済み作品が対象で、同じ作品は一度だけ処理し、ほかのソースで同じ作品を表示した場合も変更が反映されます。情報の強制更新では言語と手動編集の保持・上書きを選べ、画像の再取得ではサンプル画像を含めるか選べます。上書きタスクの作成後に情報が変更された場合、該当する処理単位の上書きは停止します。結果を確認してから再実行してください。

バックグラウンドタスクで進捗確認・中止・子タスクの失敗項目の再試行ができます。一度に一つの操作を選びます。ソースで有効な自動処理は元の設定に従って動作します。互換ソースでは作品情報・画像・再整理が使えますが、ローカルファイルのスキャンとメディア情報取得は利用できません。

商品情報や画像の再試行回数に達した場合は、バックグラウンドタスクで失敗項目を再試行してください。作品のメニューから商品情報の強制更新や画像の再ダウンロードもできます。取得済みの情報と画像は引き続き利用できます。

### 言語の表示・編集・更新

新規環境は簡体字中国語と日本語を標準で取得します。繁体字中国語・英語は設定で追加し、提供元が対応する範囲で取得します。

- 情報表示の言語を選ぶと、タイトル、紹介、人物、タグ、価格、画像をまとめて切り替えます。不足する項目は未提供と表示します。
- 編集では対象の言語を選んで保存し、その言語だけ変更します。
- 言語不明の情報は言語を指定できます。既存情報へのマージは不足分のみ、上書きはその言語全体を置き換えます。
- 一言語だけ更新する場合は個別更新から商品情報の強制再取得と言語を選びます。ほかの言語は保持し、失敗分は結果から再試行できます。
- 同じメニューから画像の補完・再取得、メディア情報取得、スキャン、再整理もできます。

タイトル、パス、情報、メッセージは選択して Ctrl+C（macOS は Command+C）、モバイルでは長押しでコピーできます。

## AI 翻訳

Android の端末内ライブラリで「AI 設定」を開き、プロバイダーを追加してキーを入力し、モデルの取得と接続テストを行います。保存後は作品の詳細から翻訳を始められます。クラウドモデルの利用にはスマートフォンのインターネット接続が必要です。

モデルの応答が遅い場合は、「ローカルゲートウェイを管理」で「リクエストのタイムアウト（秒）」を延長し、保存してから翻訳をやり直します。この設定はローカルゲートウェイからモデルへのリクエストごとに適用されます。

サーバーのライブラリでは、管理者としてログインして「AI 設定」を開きます。サーバーに接続した Android アプリでは「サーバーのゲートウェイを管理」、ブラウザーでは「ローカルゲートウェイを管理」を開きます。プロバイダーの情報を入力し、モデルを追加します。設定は両方で共有され、モデルのテストと翻訳はサーバーが行います。一覧が表示されない場合や必要なモデルが見つからない場合は、モデル ID を手入力できます。モデル ID を選択または入力すると、保存前に接続をテストできます。別名を空欄にするとモデル名が使われます。「AI 設定」に戻ると、モデル一覧が自動で更新されます。

プロバイダーの「既定のリクエスト方式」が表示される場合は、プロバイダーの案内に従って選びます。各モデルは既定の方式を使いますが、「モデルのリクエスト方式」で個別に変更できます。Responses が必要と表示されたら、「Responses で再テスト」を選びます。テストに成功したら、「保存」または「設定を保存」を選ぶと、以降の翻訳で現在の設定が使われます。

ゲートウェイの管理画面で「モデルの使用量と呼び出し履歴」を開くと、累計使用量を確認したり、UTC の日付で検索したりできます。呼び出しの詳細は既定で直近 1,000 件を保持します。同じ画面で保持上限を変更しても、累計使用量は引き続き確認できます。端末内ライブラリでも確認できます。

ゲートウェイの管理画面の「プロバイダー」で、プロバイダーごとに「プロキシ方式」を選べます。

- 既定の「システムプロキシを使用」では、ライブラリを実行している端末またはサーバーのプロキシ設定を使用します。
- 「プロキシを使用しない」を選ぶと、Ruri はプロバイダーに直接接続します。ネットワーク側の透過プロキシは引き続き適用される場合があります。
- 「プロキシを指定」では、プロキシサービスから案内された完全なアドレスを入力します。例は `http://127.0.0.1:10808` です。保存したアドレスは、含まれるユーザー名とパスワードも含めて表示・編集できます。サーバーのライブラリを使うときは、サーバーから接続できるアドレスを入力してください。`127.0.0.1` はサーバー自身を指します。

モデル一覧の取得とモデルのテストには、入力中のプロキシ設定を使います。テストではサンプルリクエストを 1 件送信するため、プロバイダーの利用枠を消費する場合があります。保存後は、そのプロバイダーへの新しいリクエストにも同じ設定が使われます。

使いたい機能のモデルを選んでその機能を有効にし、最後に AI を有効にします。選択は自動で保存されます。台本、作品情報、フォルダーやファイルの表示名を翻訳できます。オンラインモデルを使う場合は、選んだテキストがモデルサービスに送信されます。個別の翻訳は、内容を確認してから保存してください。

作品メニューまたは「作品情報を編集」画面の上部から「作品情報を翻訳」を選びます。編集画面のタイトル欄には、選択中の「作品情報の言語」のタイトルが表示されます。その言語が翻訳元になります。一括翻訳では、タイトル、概要、詳細紹介、制作スタッフ、タグ、シリーズ名など、翻訳できる項目があらかじめ選ばれています。不要な項目の選択は解除できます。個別に翻訳するには、対象の項目にある「タイトルを翻訳」や「タグを翻訳」などのボタンを選びます。翻訳先の言語に訳文がある項目は既定でスキップされます。もう一度翻訳する場合は、スキップをオフにします。

「システムプロンプトを送信する」は既定でオフです。オンにすると、中国語の既定のプロンプトを確認し、今回の翻訳で使う用語や文体を指定できます。「既定のプロンプトに戻す」で変更を取り消せます。翻訳を開始すると、選択した項目のうちスキップされなかったテキストが設定済みの翻訳サービスに送信されます。オンの場合は、今回のプロンプトも送信されます。

翻訳の開始後に「バックグラウンドに移す」を選ぶと、ライブラリの閲覧を続けられます。作品から翻訳を開き直すか、「バックグラウンドタスク」を開いて、進行状況や翻訳結果を確認します。進行中または確認待ちの翻訳は、作品ごとに一つです。「後で確認」を選ぶと結果を保持でき、結果を破棄して翻訳をやり直すこともできます。Android のアプリプロセスが終了すると端末内で進行中の翻訳は中断されます。完了済みの翻訳結果は引き続き確認できます。

「翻訳結果を確認」で原文と編集できる新しい訳文を項目ごとに比較します。翻訳先の言語ですでに保存している訳文があれば、開いて確認できます。残したい項目を選び、「保存と保護を確認」で翻訳先の言語に保存して保護します。

複数の名前を翻訳するには、フォルダーまたは作品の操作メニューで「名前を一括翻訳」を選びます。翻訳先の言語を選び、次にその言語の既存の翻訳名をスキップするかを選びます。システムプロンプトは既定で送信しません。「システムプロンプトを送信する」を選択すると、今回のプロンプトを編集し、進捗画面で確認できます。既存の翻訳名は既定でスキップされます。オフにすると、選択した言語の翻訳名を置き換えます。フォルダーでは登録済みの下位フォルダーとファイル、作品ではその作品に属するフォルダーとファイルが対象です。オンラインモデルには対象の名前が送信されます。選択した場合はプロンプトも送信されます。名前の翻訳タスクで進捗確認やキャンセルができます。保存済みの翻訳名は残ります。Android のローカルライブラリでは端末で設定したモデルを使います。

プライバシーボタンの隣にあるボタンで、フォルダーとファイルの原名と翻訳名を切り替えられます。画面の言語に対応する翻訳名を表示し、翻訳名がなければ原名を表示します。「表示名を設定」で個別の翻訳名を編集または削除できます。元のファイル名とパスは保持されます。

## コレクションとプレイリスト

作品メニューから既存または新規コレクションに作品全体を追加します。ライブラリ同様にカード・一覧で閲覧し、詳細・ファイルを開けます。情報が更新されると参照先の最新情報を表示します。

個別の音声・動画・クリップはコレクションの「音の小箱」に入り、作品風のカバーカードで表示します。開いて閲覧、再生、キューやプレイリストへの追加ができます。取り除いても元ファイルと作品への所属は保持します。

スマート発見も作品と音の小箱で表示し、ライブラリの整理に応じて更新します。「コレクションとして保存」で現在の収録範囲を編集可能なものとして保存できます。参照した作品は引き続き更新されます。一部のみ収録と表示された場合、保存対象もその範囲です。

具体的な曲、範囲、重複、順序の保存にはプレイリストを使います。キューから保存でき、コレクションへの収録は作品と個別メディアをまとめます。旧版の自作コレクションは更新時にプレイリストへ移り、多い場合は順番に分割します。曲が未保存の作品は更新時の内容で展開し、復元できない項目は説明を、見つからない保存済みファイルは利用不可と表示します。

プレイリストを開き、「すべて再生」を押すと先頭から再生します。音声または動画の項目をタップすると、その項目からリスト全体の順番どおりに再生し、前の項目には「前へ」で戻れます。「その他の再生方法」から全件のシャッフル再生やキューへの追加ができます。検索後は検索結果のみを再生することもできます。検索結果を直接タップした場合は、リスト全体をその項目から再生します。

項目のメニューでは、その項目だけの再生、次の再生、キューへの追加、ファイル・作品の詳細表示ができます。「ここからキューに追加…」では、その項目以降を次またはキューの最後に追加できます。グループの見出しは展開に使い、グループの再生はメニューから選びます。利用できない項目はタップしても再生できません。プレイリストの編集は現在のキューを変更しません。

## 再生と続きからの再生

音声と動画は、同じフォルダーにある同名字幕を優先します。ない場合は、同じ作品・ソース内の別フォルダーから同名字幕を探し、一定の順序で最初の候補を選びます。字幕を専用フォルダーに置くこともできます。先にファイルをスキャンして作品として整理してください。台本の字幕メニューでは、現在のフォルダーに字幕がある場合も別の候補へ切り替えられます。ログイン中に手動で選んだ字幕や字幕オフは、そのファイルの設定としてアカウントに保存され、次回の再生時に復元されます。自動選択は保存済みの選択を上書きしません。選んだ字幕が利用できない間は最初の利用可能な候補を使い、元の選択は保持します。ゲストの選択はアカウントに保存されません。オフライン再生では引き続き端末の選択を使います。字幕の時刻は元のままなので、必要に応じて台本の時刻を調整してください。共有字幕の編集は現在のメディアの隣に新しいファイルとして保存され、別フォルダーの原本は変更しません。

作品やフォルダーから再生し、効果音や WAV など利用可能な版・形式を選びます。履歴から続きを開き、よく聴くものをキュー、プレイリスト、コレクションに追加できます。

音声ページ、下部の操作、台本ウィンドウ、ローカル再生には 10 秒戻る・進むがあります。一時停止中の移動では停止を保ちます。長さ未取得・読み込み中はお待ちください。バーをドラッグすると移動先と利用可能な画像を表示します。再生オプションで字幕、音声トラック、チャプターを選び、不足時はメディア情報を取得してください。

読み込み中やバッファリング中も再生ボタンから一時停止できます。停止すると、読み込み完了後も勝手に再生されません。再生に失敗した場合は「再試行」で現在の位置から読み込み直せます。再生ページに作品名が表示されている場合は、名前をタップして詳細を開けます。戻っても現在のキューを使い続けられます。進行バーではスクリーンリーダーが現在の時間と全体の長さを読み上げます。

音声の進行バーをドラッグすると、横の時刻に移動先を表示し、指を離すと移動します。曲の切り替えや読み込みが始まると、途中のドラッグは取り消されます。音量ボタンから割合を確認・調整できます。スリープタイマーのメニューには選択中の設定にチェックが付き、塗りつぶされた月のアイコンは有効であることを示します。表示する分数は選択した長さです。

時間付き台本は現在の行を表示します。縦画面では横ハンドルをドラッグして大きさを変更し、タップで一行・複数行を切り替えます。横画面では縦ハンドルで幅を変え、タップで隠します。大きな Web 画面では右下に台本が開き、上のハンドルで高さ調整・非表示にできます。下部の台本ボタンで再表示し、閲覧中も維持します。時刻の調整や、カバーと台本を表示する全再生画面への移動も可能です。

Android の時間付き台本で「フローティング字幕」を選び、ほかのアプリ上への表示を許可して戻り、もう一度押します。字幕は Ruri 内でもほかのアプリ上でも表示されます。ロック中は非表示になり、解除後に再び表示されます。通常は現在と次の行だけを表示します。字幕をタップすると閉じるボタンが現れ、上下ドラッグで位置を調整できます。操作せずに 3 秒経つとボタンが隠れます。閉じるには字幕をタップしてから右上の × を押してください。動画の全画面では Web の Space で停止・再開、矢印で移動、Esc で戻ります。Android はタップで操作、左右のダブルタップで 10 秒移動します。寝る前はスリープタイマーを利用できます。

管理者は台本メニューから作成・編集・形式変換し、プレビューして保存できます。読み取り専用フォルダーなら Ruri 内に保存し、メディアの隣に置く場合は書き込み権限を確認します。変換後は時刻とスタイルを確認してください。

### メディアツールの準備

Linux・Windows・Docker のリリースには FFmpeg と FFprobe を同梱します。対応するローカルファイルの変換、音量正規化、プレビュー、音声トラック、内蔵字幕に利用でき、形式と取得済み情報によって利用可否が異なります。読み取り可能な互換ソースの動画も、対応する画質で変換再生できます。Linux は全体を展開し、`media-tools` をプログラムの隣に置いてください。

管理画面の解析ツールで確認します。独自ツールは `fd` 入力対応版を用意し、両方のフルパスを指定してテスト後に保存します。空にして保存すると標準に戻ります。自動取得にはサーバーのインターネット接続と約 500 MB の空きが必要です。

### ほかのプレーヤー・ファイル管理アプリから接続

WebDAV 接続を作り、`http://サーバー:ポート/dav/` または `https://証明書のサーバー名:ポート/dav/`、現在の Ruri のユーザー名・パスワードを指定します。`/dav/` を二重に付けないでください。例：`http://192.168.1.20:18080/dav/`、Nginx 経由なら `https://ruri.example.com/dav/`。サーバーへのアクセス権があるアカウントを使用してください。

フォルダーから元ファイルを再生できます。読み取り専用で、アップロード、削除、改名、変換、ほかのプレーヤーとの再生位置同期はできません。新規ファイルは Ruri でスキャン後に表示し、再生形式は利用アプリに依存します。

Windows エクスプローラーは「PC → ネットワークの場所を追加」でカスタムの場所と完全な URL、認証情報を入力します。ブラウザーやアドレス欄への貼り付けだけでは場所は登録されません。

Windows WebClient は標準で HTTPS 以外のパスワード認証を拒否します。HTTP でパスワードが繰り返し求められる、名前がない、エラー 67 などはこの制限の可能性があります。HTTP 対応クライアントか、正しい名前と信頼済み証明書の HTTPS を使用してください。ブラウザーの警告を無視しても Windows の信頼は設定されません。

信頼できる家庭内 LAN に限り HTTP 認証を許可する場合、`services.msc` で WebClient を確認し、管理者 PowerShell で実行します。

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\WebClient\Parameters' -Name BasicAuthLevel -PropertyType DWord -Value 2 -Force
Restart-Service WebClient
```

この変更は Windows 全体の WebDAV に適用され、HTTP のパスワードは暗号化されません。再起動で既存接続は切れます。HTTPS 専用へ戻すには `-Value 1` で実行します。サービスがない・組織の制限がある場合は専用クライアントを使ってください。[Microsoft の説明](https://learn.microsoft.com/en-us/iis/publish/using-webdav/using-the-webdav-redirector)も参照できます。

| 症状 | 対処 |
| --- | --- |
| Web 画面も開かない | アドレス、Docker 外部ポート、ファイアウォール、LAN 範囲を確認 |
| パスワード変更後に失敗 | 切断し、資格情報マネージャーの Windows 資格情報から旧記録を消して再接続 |
| ブラウザーで `/dav/` が未対応メソッド | WebDAV クライアントに登録する。Web 用の一覧ページではありません |
| 大きなファイルが失敗、`0x800700DF` | HTTPS でも WebClient の単一ファイル制限があります。専用アプリか Microsoft の `FileSizeLimitInBytes` を確認 |
| 大量のファイルがあるフォルダーのみ失敗 | WebClient のプロパティ容量制限があります。メディアを移さず別アプリを利用 |
| 削除・アップロード・改名不可 | 読み取り専用の仕様です |

## お気に入りクリップ

王冠はライセンス機能の印です。再生可能で長さを取得済みのファイルを開き、必要なら管理者に有効化・更新を依頼します。再生中または動画全画面のオプションからクリップを選び、二つのハンドルで範囲を指定します。標準は現在位置から 30 秒、末尾近くは最後の 30 秒です。拡大して細かく調整できます。試聴は終了位置で停止し、保存・取り消し後は元の位置に戻れます。

アカウントメニューから再生、キュー、プレイリスト、コレクションへの追加や範囲編集ができます。削除で一覧内の参照も消えますが元メディアは保持します。ファイルがない・ライセンス期限切れでもクリップは保持され、復旧・更新後に使えます。

## Android で聴く

[公式リリースページ](https://github.com/rurimecha/rurimecha/releases/latest)から端末に合う APK を取得します。一般的なスマートフォンは `arm64-v8a`、32 ビット ARM 端末は `armeabi-v7a`、x86-64 端末は `x86_64` を選びます。旧版アプリで更新をダウンロードできない場合は、リリースページから対応する APK を取得して上書きインストールすると、端末内のデータが引き継がれます。

Android のホームから「この端末のライブラリ」と「サーバーに接続」を直接開けます。端末内のファイルを整理するには、ライブラリでフォルダーを追加し、システムの選択画面でアクセスを許可します。スキャン後はフォルダーや作品から探して再生できます。フォルダーを追加したりライブラリから外したりしても元のファイルは残ります。開けなくなった場合は、フォルダーを選び直してください。

ローカルライブラリの「バックグラウンドタスク」で、スキャン、整理、メディア情報の取得を確認できます。アプリが終了してスキャンが中断された場合は、ローカルライブラリを開き直してください。個別の作品やフォルダーを更新するには、そのメニューから更新項目を選びます。「フォルダー」から ASMR.one を見たり、Kikoeru 互換ソースを追加したりして、作品から端末に保存するファイルを選べます。

ローカル再生設定で音量の正規化を有効にすると、再生中に音声トラックを測定します。測定が終わるまで元の音量で再生します。「互換コピーで再生」から端末で対応する画質を選ぶと、コピーを作成し、現在位置から再生を続けます。いつでも元のファイルに戻せます。「埋め込み字幕を抽出」ではテキストトラックを選び、システムの選択画面を使って WebVTT として保存できます。

サーバーの作品を聴く場合は「サーバーに接続」を選び、LAN 検出またはアドレス入力で接続してログインします。接続できないときはサーバー選択画面に戻ります。同じアドレスで試し直すか、別のサーバーを選べます。検出できない場合は、端末とサーバーが同じ LAN にあり、サーバーで自動検出が有効かを確認してください。

再生前でも「マイ → 再生設定」でソースへの直接接続を切り替えられます。オンはスマートフォンから接続し、サーバーのプロキシが必要・直接再生できない場合はオフにします。再生詳細からも設定できます。

### 保存してオフラインで聴く

1. 作品で版・形式を選び、「端末にダウンロード」でファイルを選択します。ファイルメニューから単体も保存できます。ダウンロード時は元のサーバーにログインします。
2. メニューや作品の詳細から「ダウンロードタスク」を開き、サーバーからのダウンロードの進捗確認、一時停止、再開、キャンセルを行います。キャンセルしても完了したファイルは残ります。
   「端末内のダウンロードを削除」を選ぶと、端末のライブラリとアプリの保存領域から削除できます。自分で選んだフォルダにあるファイルは、端末のファイル管理アプリから削除できます。
3. 完了したファイルをオフラインで聴くには、「この端末のライブラリ → フォルダー」で「ダウンロード済み」を開きます。更新後に端末のライブラリを開くと、以前ダウンロードした作品もここに表示されます。ログアウトやサーバーを変更した後も再生できます。

保存場所を選ぶには、メニューやダウンロード画面から「ダウンロード先」を開き、「フォルダーを選択」でアクセスを許可します。今後サーバーや端末内ライブラリのオンラインソースからダウンロードするファイルがそのフォルダーに保存されます。すでに保存したファイルは現在の場所に残ります。既定の保存先に戻すには「アプリのストレージ」を選びます。フォルダーを使えなくなった場合は、選び直してアクセスを許可してください。

サーバーから保存できるのは、元の音声・動画、保存済みの文章、カバー、利用可能なテキスト字幕です。端末が元の形式に対応しない場合は、サーバーで別の形式を選んでダウンロードしてください。既定では Wi-Fi と有線ネットワークのみを使います。制限を解除するとモバイル通信を使う場合があります。一度に最大 500 ファイルを保存でき、サーバーからのダウンロードは最大 500 版を保持できます。

端末での再生は、バックグラウンド再生、通知からの操作、リピート、シャッフル、タイマー、台本、全画面動画に対応します。キュー、お気に入り、再生位置は端末に保存されます。キューを復元した直後は一時停止しています。アプリのアンインストールやデータ消去で、アプリのストレージ内のダウンロードと端末内の記録が消えます。選んだフォルダーのファイルは端末のファイル管理アプリから確認できます。サーバーに保存したクリップは、有効化済みの元のサーバーに接続すると再生できます。

## プライバシーモードと再生履歴

画面やプレーヤーの目のボタンでカバー、画像、動画を隠し、タイトル、タグ、ファイル名、字幕を伏せ字にします。小さい目で 3 秒だけ確認できます。ナビゲーションやバーは利用でき、設定は端末に保存します。

Android ではこのモードのスピーカー再生前に確認します。ヘッドホン・Bluetooth 切断で停止し、再接続後は手動で再開します。通知やメディアキーで確認が必要ならアプリを開きます。ロック画面・通知の文章とカバーも隠します。

再生位置は引き続き保存します。履歴から個別削除・全削除すると位置と完了状態も消します。コレクション、プレイリスト、クリップ、メディアは保持します。再生中の履歴を消しても聴き続けられ、選び直すと再び記録します。

## サーバーライセンスとアカウント

サーバーで「サーバーライセンス」を開くと、お気に入りクリップ、AI、スマート接続を有効にできます。Android でサーバーに接続中は、そのサーバーのライセンスを使用します。端末内ライブラリのライセンス設定では、端末内のお気に入りクリップ、作品情報の翻訳、スマート接続を有効にできます。同じキーで両方を有効にでき、1 台につき 1 枠を使用します。

端末をインターネットに接続して「ライセンスを有効化」を選び、ライセンスキーを入力します。端末名は既定のままでも、「リビングのパソコン」など見分けやすい名前に変えても構いません。有効化後は端末名、有効期限、利用できる機能を確認できます。更新の手続き後は「ライセンスを更新」を選び、元のキーを入力します。有効化、更新、紐付けの解除にはインターネット接続が必要です。有効期限まではオフラインでも使用できます。提供元による取り消しは、現在の期限が切れるか、次回オンラインでライセンスを操作したときに反映されます。

有効化または更新の際、取得できる場合はサーバーのホスト名または Android の機種名がライセンスサービスに送られ、同サービスの管理者が端末の確認に使います。公式サイトでライセンスを確認すると、ライセンス画面で指定した端末名と種類が表示されます。

端末を変更する前に「紐付けを解除」を選ぶと、データとメディアを保持したまま 1 枠を解放できます。解除が未完了の場合は、インターネットに接続して再試行してください。コンテナのイメージを更新するときは、データボリュームと設定済みのホスト識別子を保持します。

旧端末を操作できない場合は、[公式サイト](https://rurimecha.top/ja/)でライセンスを確認します。最初のメールを開いて「ライセンスを表示」を押し、端末名と種類を確認してください。旧端末の利用枠の解放を申請し、2 通目のメールから確定します。リンクはそれぞれ 15 分間有効です。解放後、ライセンスが有効なら元のキーで新しい端末を有効化できます。旧端末のオフラインライセンスは期限まで使える場合があります。元のメールアドレスを利用できない場合は、購入情報を用意して提供元にお問い合わせください。

提供元から別のアドレスを案内された場合は「詳細設定」で HTTPS アドレスを入力して保存します。空欄で保存すると既定のサービスに戻ります。変更後も現在のライセンスは使えます。

サーバーライセンスを有効にすると、管理者はユーザー管理でアカウントを作成できます。ライセンスが無効になると、組み込み管理者以外はログインとアクセスが停止します。アカウントとデータは保持されます。再有効化したら、対象のユーザーはログインし直してください。メディアライブラリは共有され、コレクション、リスト、設定、再生位置はアカウントごとに保存されます。アカウントを無効にすると、そのログインと WebDAV アクセスが終了します。更新後に求められたら、ログインし直してください。

「アカウントとセッション → ログインセッションと WebDAV」で端末名、種類、ログイン IP、日時・期限を確認し、不要なログインを解除できます。IP はログイン時のもので、後のネット変更は追いません。ブラウザーは種類と OS、Android は機種、デスクトップは PC 名を表示します。終了・期限切れの履歴はここには保持しません。

## 接続とネットワーク

### ほかの端末から接続

Linux は標準で `http://サーバーLANアドレス:8080/` に接続できます。ファイアウォールを確認してください。Windows はインストール時の設定（初期値は全 IPv4 の 8080）を使い、インストール先の `rurimecha-core.exe` をプライベートネットワークで許可します。`127.0.0.1` だけなら、それを保持して LAN の待ち受けを追加してください。スリープ、電源オフ、終了中はほかの端末から再生できません。Docker はホスト IP と外部ポートを使います。

LAN 範囲が空なら直接つながるプライベート範囲を判定します。手動は `192.168.1.0/24` のように 1 行一つで、Docker・VPN・別範囲を追加するときは現在の値も保持します。外部接続はサーバー全体とアカウント両方のリモート許可が必要です。HTTP のログイン・メディアは暗号化されないため、外では HTTPS または信頼できる VPN を使います。

### HTTPS の有効化

HTTP を保持するか、HTTPS も異なるポートで有効にします（初期値 `8443`）。PEM 証明書と対応する未暗号化の秘密鍵を指定し、交換時は両方選び直します。証明書に含まれる名前・IP で接続し、端末で信頼してください。HTTP で送る場合は信頼できる LAN 内で行います。強制 HTTPS では HTTP を転送しますが、プレーヤー・WebDAV は HTTPS を直接指定してください。変更は切断を伴うため新アドレスを控えます。

Docker は `"192.168.1.20:8443:8443"` などのマッピング追加後に `docker compose up -d` を行います。転送を使う場合は HTTPS の内外ポートを合わせてください。Nginx を使う場合は次の手順に従います。

## Nginx 経由の接続

Nginx、ドメイン、証明書のある方向けです。家庭内だけなら直接接続できます。Nginx で HTTPS を提供し、Ruri へ HTTP で接続できます。同じ証明書を Ruri にも登録する必要はありません。同一ホストの Nginx は標準 Docker ブリッジを含め信頼するプロキシの入力不要で、訪問者 IP で権限を判断します。専用ドメインのルート `https://ruri.example.com/` を使い、`/ruri/` のようなサブパスには対応しません。HTTP は信頼できる経路で、HTTPS 上流では証明書検証を設定します。

### 例：同一ホストの Nginx で HTTPS

1. ドメインを Nginx に向け、端末が信頼する一致した証明書を用意します。例は `/etc/nginx/certs/ruri-fullchain.pem` と `/etc/nginx/certs/ruri-key.pem` です。
2. 同じホストなら信頼するプロキシは空のままです。Nginx 専用なら Ruri を `127.0.0.1:8080` にし、LAN 範囲は現在の値に家庭内範囲 `192.168.1.0/24` などを追加します。
3. Debian/Ubuntu では `/etc/nginx/conf.d/ruri.conf` を作り、ドメイン・パスを置き換えます。

```nginx
server {
    listen 80;
    server_name ruri.example.com;
    return 308 https://ruri.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name ruri.example.com;
    ssl_certificate     /etc/nginx/certs/ruri-fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/ruri-key.pem;

    client_max_body_size 257m;
    client_body_timeout 600s;
    send_timeout 600s;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header Connection "";

        proxy_buffering off;
        proxy_request_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_redirect off;
        gzip off;
    }
}
```

4. `sudo nginx -t`、`sudo systemctl reload nginx` を実行します。
5. `https://ruri.example.com/` でログイン、設定保存、再生・移動を確認し、WebDAV は `/dav/`、移行アップロードも同じ入口を使います。

これは利用者から直接受ける一段の Nginx の例です。CDN 等が前にある場合はそこで信頼する入口を限定し、利用者アドレスを復元してください。利用者が自由に送るヘッダーを信用せず、自分のプロキシ・専用範囲だけ信頼します。外部接続には双方のリモート許可が必要です。家庭内専用ならオフのまま、HTTPS server に `allow 192.168.1.0/24; deny all;` を追加できます。信頼できない上流は HTTPS・信頼できるトンネルを使います。

認証情報、Cookie、Origin、Referer を保持し、偽装や不要な書き換えをしないでください。Authorization を占有する Nginx の Basic 認証は競合します。PROPFIND を許可し、メディア、画像、ログイン応答を公開キャッシュしないでください。

### Docker と HTTPS 上流

- Ruri のみ Docker：標準ブリッジと `127.0.0.1:8080:8080` を保持し、ホストの Nginx は `http://127.0.0.1:8080` に接続します。再作成で信頼プロキシの変更は不要です。家庭内 LAN 範囲を設定します。
- 両方 Docker：専用ネットワークと `http://core:8080` を使います。localhost は Nginx 自身です。Nginx の固定 IP または専用範囲のみ信頼し、他ユーザーと共用の範囲は指定しません。Ruri のホストポート公開は不要です。
- HTTPS 上流：Ruri の HTTPS を有効にし、`https://127.0.0.1:8443` または `https://core:8443` と以下を使います。

```nginx
proxy_ssl_server_name on;
proxy_ssl_name ruri.example.com;
proxy_ssl_verify on;
proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
proxy_ssl_verify_depth 3;
```

名前は上流証明書に含まれる必要があります。私設 CA はルート証明書のパスに変え、検証はオフにしないでください。

### よくある問題

| 症状 | 確認 |
| --- | --- |
| ログイン・保存で 403 | LAN・リモート権限、例の設定、別端末・コンテナーのプロキシの信頼アドレス |
| 転送ループ・8443 に移動 | プロキシ設定と信頼。Nginx だけが HTTPS の場合は Ruri の強制転送を解除 |
| 502 | 起動、上流アドレス・ポート、HTTPS の名前・ルート証明書 |
| ページだけ開き再生・移動不可 | Range を保持し、メディアキャッシュ・バッファを無効化して直接再生を確認 |
| 移行アップロード 413 | `client_max_body_size` と Ruri の容量制限 |
| WebDAV 一覧不可 | `/dav/`、認証、PROPFIND |

## 引っ越しと復元

旧サーバーの管理者で移行と復元を開き、全作品情報、システムデータ、両方から選びます。システムにはアカウント、設定、コレクション、位置が含まれ、パスワードが必要です。パッケージとパスワードを保管してください。メディアを別途移し、新サーバーでログイン後、パッケージと新パスを指定して復元をプレビューします。不足を確認して実行します。不足ファイルでも情報や保存項目・位置を保持でき、元の相対位置に置いてスキャンすると再生できます。システム復元後は再起動し、旧アカウントでログインします。

一作品だけなら作品の移行から出力します。相対パスが同じなら移行先の同じ操作で情報と手動整理を置換し、まだないなら全体の移行画面から取り込みます。情報、出典、編集、画像と更新設定を保持します。元メディア、ログ、タスク記録、サーバーライセンス、スマートフォンの保存は別途扱います。

## 管理者パスワードのリセット

- Linux サービスは `sudo /opt/rurimecha/reset-admin-password.sh --service`。実行中なら再起動します。手動環境は停止して展開先で `./reset-admin-password.sh` を実行し、別データパスは引数に追加して再起動します。
- Windows は通知領域から終了し、インストール先（標準 `%LOCALAPPDATA%\Programs\Rurimecha`）の `reset-admin-password.cmd` を実行して開き直します。別データパスならその場所のコマンドプロンプトで `reset-admin-password.cmd "データパス"` を実行します。
- Docker は Compose と同じ場所で `./reset-admin-password.sh` を実行します。起動中なら一時停止して再起動します。

表示されたユーザー名・新パスワードでログインします。名前とデータは保持し、同アカウントの端末は再ログインが必要です。

## ゲスト体験

有効なサーバーライセンスで管理者がユーザー管理のゲスト体験を有効にすると、ログイン画面からパスワードなしで閲覧・再生できます。編集、コレクションや位置の保存はできません。無効化で利用を終了し、再有効化後は入り直せます。公開デモは公開再生が許可された専用ライブラリを使ってください。

## 表示言語の選択

接続・ログイン画面やアカウントメニューの言語ボタンで 简体中文、繁體中文、日本語、English、システムに従うを選べます。ログイン後は外観と閲覧設定からも変更でき、アカウントに保存してほかの端末でも使います。未ログインの選択はその端末だけに保存し、ログアウト後に戻ります。ローカルライブラリはオフライン時に直近の言語を使います。

システムに従う場合は対応する端末言語を優先し、繁体字地域は繁体字、ほかの中国語地域は簡体字、対応言語がなければ英語です。翻訳名の表示中は、ファイルとフォルダーの翻訳名が画面の言語に従います。作品情報、音声、字幕の言語はそれぞれのメニューで選べます。インストーラーは簡体字中国語、管理・コマンドラインツールは原則英語、過去のリリースノートは中国語と英語です。


## サークル・声優・イラストレーター

「声優」には最初にライブラリ内の声優を表示します。項目を選ぶと登録作品を確認できます。「ほかの声優」で人物を探し、「プロフィールを見る」で紹介・タグ・出演作品を開きます。ライブラリ内の人物の作品画面からもプロフィールを検索できます。情報は可能な場合に現在の表示言語で表示し、「情報の言語」で原文を切り替えます。空の言語見出しは表示しません。ライブラリ内の作品を開き、複数のコピーがある場合は選択できます。未登録作品はASMR.oneで探せます。「ASMR.oneの作品を見る」でその声優の作品を表示します。自動追加やダウンロードは行いません。

「サークル」「イラストレーター」では、ライブラリの作品とDLsiteまたは互換ソースでの作品検索を引き続き利用できます。DLsiteの結果は商品情報を開くもので、ダウンロード機能ではありません。


## 変更がないときの自動確認

定期確認で変更が見つからなければ、整理、作品情報取得、メディア情報抽出を繰り返しません。既存の保留処理や再試行は引き続き実行します。

## 問題の確認と詳細な診断

管理者は設定からシステムログを開けます。通常は「要確認」で問題を確認し、「すべての記録」で操作結果を表示できます。問題を報告するときは詳細を開いて記録を確認してください。進捗、失敗した項目、再試行方法はタスクの詳細にあります。

終了したタスクと実行ログは最大 48 時間保存されます。未完了の項目はタスクの詳細から再試行できます。記録の保存期間が過ぎた場合は、作品やソースから操作し直してください。

調査時は管理ページの「詳細な診断」を有効にして保存し、問題を再現した後に無効にして保存します。設定はサーバー全体に適用され、再起動後も保持されます。無効化後は新しい診断記録を追加しません。既存の記録は容量制限内で保持され、ログの「診断記録」で確認できます。通常の利用では無効のままで構いません。


## リスニング統計とおすすめ

サイドバーまたはアカウントメニューから「リスニングとおすすめ」を開きます。「リスニング統計」では再生時間、カレンダー、月別の推移、よく聴く作品・声優・サークル・タグを確認できます。過去30日、12か月、年、全期間を選べます。ローカルライブラリの統計は端末に保存されます。サーバーの統計は、そのサーバーに接続して確認できます。

作品詳細で「自分の評価」を選び、星1～5つで評価できます。もう一度開くと変更や取り消しができます。評価はアカウントごとに作品全体へ付け、形式や再生グループで共通です。カードには公開評価と自分の評価を分けて表示します。

「あなたへのおすすめ」では、好みに合いそうな作品、いつもと違う作品、久しぶりに聴く作品を選べます。作品詳細を開いたり、直接再生したりできます。「おすすめを入れ替える」で候補を変更します。再生位置の記録を削除しても、統計と評価は残ります。


### 動画の画質と変換制限

動画再生中にプレーヤー設定の「動画の画質」を開きます。変換に対応する動画では解像度とビットレートを選択でき、切り替え後はバッファリングして現在位置から再開します。変換できない動画には元の形式だけを表示します。ローカルソースと読み取り可能な kikoeru 互換ソースの動画に対応します。元の形式を再生できるかは端末によります。互換再生の「自動」は既定の画質予算を使い、回線速度に応じた継続的な自動調整は行いません。

管理者は解析設定で変換後の最大高さ、動画ビットレート、処理ごとの最大ワーカースレッド数を指定できます。高さとビットレートの 0 は制限なしです。スレッド数は 1～64、0 は 1 ワーカーです。制限は新しい変換処理に適用され、元の形式の直接再生には影響しません。元ファイルを保持し、画像を拡大せず元のフレームレートを保ちます。

## 作品の削除と除外管理

管理者は作品詳細の「その他の操作 → 作品を削除」から作品を削除できます。作品情報、取得した情報、手動編集、および全ユーザーのコレクションやプレイリストの作品参照を消去します。元のメディアとダウンロード済みファイルは残ります。作品のファイルと通常のサブフォルダーは無視され、親作品に取り込まれたり未登録一覧に表示されたりしません。独立した子作品は残ります。RJ などの番号がある場合、すべてのソースで同じ番号の再登録を防ぎます。番号がない場合は元のフォルダーのみが対象で、移動や名前変更後は再登録される可能性があります。

「管理 → 除外管理」で削除した作品と無視したフォルダーを確認し、除外を解除できます。その後、ローカルの作品は再整理し、互換サービスの作品は明示的に再登録してください。消去した情報、評価、コレクション参照は復元されません。他の除外設定は引き続き適用されます。関連タスクの実行中は、完了を待つか停止してから削除してください。

### オンライン音声と接続テスト

Kikoeru 互換ソースのアドレスと必要に応じてプロキシを入力し、保存前に「接続をテスト」を選択してください。追加済みのソースでもテストできます。成功はライブラリを閲覧できることを示し、音声のダウンロード速度を保証するものではありません。

サーバーに保存が完了していない ASMR.one の音声では、プレーヤーで「スムーズな再生を優先」または「音質を優先」を選べます。前者は提供されている場合に小さい音声を使用し、後者は選択した元ファイルを再生します。切り替えても現在位置から続けられます。保存済みのファイルはローカルの元ファイルで再生し、ダウンロードも元ファイルを保持します。次の曲の先読みは、現在の曲の読み込みが完了してから始まります。
