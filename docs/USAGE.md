# Rurimecha 使用手册

**想先看看怎么用？** 打开[演示站](https://asmr.rurimecha.top/)，在登录页选择「游客体验」，即可浏览和播放演示作品；游客的收藏和收听进度不会保存。Ruri 不提供音声作品，请添加自己提供的媒体文件夹。

**选择适合的使用方式：** Windows 可以使用 MSI 安装程序，无需命令行；Linux 和 Docker 按下文安装。Android 需要连接已运行的 Ruri 服务器。内置管理员无需授权即可使用网页和 WebDAV；Android 在线播放、下载和珍藏片段需要有效服务器授权。下载到手机的内容完成后可离线收听。

**费用说明：** 测试期间免费。未来收费暂定人民币 10 元／月、60 元／年或 90 元永久授权，可绑定 3 台服务器，Android 等客户端不单独占用绑定名额；最终方案以正式公布为准。已有免费功能不会改为付费。当前免费测试授权需申请审核，发放后须在 7 天内首次激活，首次激活后可使用 31 天。

## 安装与首次登录

从发行页下载对应的包，并按页面上的 SHA-256 校验。服务器支持 Linux x86-64、Docker Linux x86-64 镜像和 Windows x64。Android 手机安装包需要另外下载，手机要连接一台已经运行的 Ruri。[发行下载](https://github.com/rurimecha/rurimecha/releases)

先完成下面一种安装，再按[首次设置管理员密码](#首次设置管理员密码)操作。自己的电脑就是服务器时，直接在这台电脑上打开；装在 NAS 或另一台电脑上时，使用那台设备的局域网地址。

### Windows 安装

1. 下载 `.msi` 安装包并双击打开向导，点「下一步」，选择安装目录。安装包仅支持「为当前用户安装」，无需管理员权限；默认目录为 `%LOCALAPPDATA%\Programs\Rurimecha`，开始菜单入口也仅对当前 Windows 用户可见。其他 Windows 用户需要分别安装。若曾安装旧版 EXE 安装包，先在 Windows 设置中卸载旧版，再安装 MSI；媒体库资料会保留。
2. 设置监听 IP 和端口，再点「下一步」检查是否可用。首次安装默认 IP 为 `0.0.0.0`、端口为 `8080`，表示接收这台电脑所有 IPv4 地址上的连接；只供本机使用时填 `127.0.0.1`。选择某个 IP 时，必须填写这台电脑实际拥有的地址。端口被占用时，退出占用它的程序或改用其他端口，再重试。升级或重新安装默认沿用已有网络设置。
3. 确认安装，完成后从开始菜单打开 **Rurimecha**。如提示缺少 WebView2，安装微软的 [Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 后重新打开。
4. 在窗口顶部点「Ruri → 打开数据文件夹」，用记事本打开 `setup-code` 文件，复制设置码，返回 Ruri 完成首次设置。

点窗口右上角的 × 会隐藏到系统托盘，Ruri 继续运行。双击托盘图标可重新打开；需要完全关闭或安装更新时，在托盘图标上点右键，选择「退出 Ruri」。让其他设备访问的方法见[连接与网络](#连接与网络)。应用数据保存在 `%LOCALAPPDATA%\Rurimecha\data`，更换程序安装目录不会移动这些数据。

### Linux 安装

1. 下载 Linux x86-64 服务器包并完整解压。在解压目录打开终端，运行：

   ```sh
   sudo ./install.sh
   ```

2. 在安装提示中填写监听 IP 和端口，直接回车使用 `0.0.0.0` 和 `8080`。安装会检查地址是否可用、端口是否被占用；检查失败时不会覆盖已有网络设置。安装后会启动 Ruri，并在开机后自动运行。使用默认设置时，可从另一台电脑打开 `http://服务器的局域网地址:8080/`，服务器本身不需要图形界面。
3. 在服务器终端运行下列命令，复制输出中的设置码：

   ```sh
   sudo journalctl -u rurimecha.service -g 'Ruri administrator setup code:' -n 1 --no-pager
   ```

服务安装需要 systemd；随包音视频工具要求 glibc 2.35 或更新版本，例如 Ubuntu 22.04 或 Debian 12。应用资料保存在 `/var/lib/rurimecha`。Ruri 以 `rurimecha` 用户运行，这个用户需要能读取媒体文件夹及其上级目录；不要为解决读取问题把整块媒体盘设为所有人可写。

也可以直接指定安装时的监听地址和端口，例如：

```sh
sudo ./install.sh --listen-ip 192.168.1.20 --listen-port 18080
```

把 IP 换成这台服务器实际拥有的地址。`0.0.0.0` 表示全部 IPv4 地址，`127.0.0.1` 表示只允许本机连接。无交互安装时，新安装使用默认地址和端口；已有安装在未指定参数时保留原网络设置。升级时也可以在提示中选择保留已有设置。

不安装服务也可以在解压目录运行 `./rurimecha-core -data-dir ./data`，并保持终端运行；设置码会显示在终端中。这种方式的数据在所选目录内，升级时继续使用同一个目录。

### Docker 安装

以下以已安装 Docker 和 Docker Compose 的 Linux 电脑或 NAS 为例，使用公开仓库提供的 `compose.yaml`。NAS 的容器管理界面也可以填写相同的镜像、目录映射和端口。镜像需要 x86-64 设备，ARM 设备不能直接使用此包。

**1. 准备文件和媒体目录。** 下载 [compose.yaml](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/compose.yaml) 和 [reset-admin-password.sh](https://raw.githubusercontent.com/rurimecha/rurimecha/main/packaging/docker/reset-admin-password.sh)，放在同一文件夹。在 `compose.yaml` 旁新建一个名为 `.env` 的文本文件，填写：

```dotenv
RURI_IMAGE=docker.io/rurimecha/rurimecha:<版本号>
RURI_MEDIA_DIR="/srv/media/音声"
```

把 `<版本号>` 换成发行页给出的版本，**不保留尖括号**；把第二行换成这台 Docker 主机上已经存在的媒体文件夹。想跟随最新正式版时，可用 `RURI_IMAGE=docker.io/rurimecha/rurimecha:latest`。Windows 的 Docker Desktop 使用 Linux 容器时，媒体路径可写为 `D:/ASMR`，并允许 Docker 访问该磁盘。

这个文件夹会在 Ruri 中显示为 `/media/library`。添加媒体时选择这个路径，不要填写宿主机的 `/srv/media/音声` 或 `D:/ASMR`。示例以只读方式打开媒体；手工台本可选择「保存到 Ruri」，无需开放媒体写入权限。

**2. 启动并完成首次设置。** 在 Compose 文件所在目录运行：

```sh
docker compose up -d
docker compose logs core
```

在日志中找到 `Ruri administrator setup code:` 开头的一行，复制设置码。在运行 Docker 的电脑上打开 `http://127.0.0.1:8080/` 完成设置。手机上的 `127.0.0.1` 指手机自己，不能用来访问这台电脑。

**3. 让手机或其他电脑连接。** 不需要其他设备访问时，保留示例设置即可。需要局域网访问时，同时完成以下两项：

- 在 Ruri 的「网络设置」查看并记下「当前局域网范围」。在「局域网范围」中保留这些原有网段，再另起一行加入家庭网络的网段。例如设备地址为 `192.168.1.x`、子网掩码为 `255.255.255.0` 时，填 `192.168.1.0/24`。Docker 中自动识别的网段可能不包含家庭网络；只改端口映射仍可能被拒绝。监听地址保持默认全部 IPv4 地址，不填容器里并不存在的宿主机 IP。
- 编辑 `compose.yaml` 中 `ports` 的一行。假设 Docker 主机的局域网地址是 `192.168.1.20`，希望从 `18080` 端口访问，改为：

  ```yaml
  ports:
    - "192.168.1.20:18080:8080"
  ```

保存后运行 `docker compose up -d`，手机和其他电脑用 `http://192.168.1.20:18080/` 访问。原来的 `http://127.0.0.1:8080/` 不再是这份映射的入口。把示例 IP 换成自己设备的地址，并在主机防火墙中允许家庭网络连接该端口。

端口映射可以这样读：**在哪个主机地址接收：对外端口：Ruri 内部端口**。

| Compose 中的设置 | 应使用的地址 | 适合谁 |
| --- | --- | --- |
| `127.0.0.1:8080:8080` | Docker 主机上打开 `http://127.0.0.1:8080/` | 仅本机，或由同机 Nginx 中转 |
| `192.168.1.20:18080:8080` | `http://192.168.1.20:18080/` | 指定局域网地址上的其他设备 |
| `8080:8080` | 主机各地址的 `8080` 端口 | 会监听全部主机地址，需自行限制访问范围 |

只更换对外端口时，修改中间的数字，最后的 `8080` 保持不变，也不需要改 Ruri 的内部端口。可以运行 `docker compose ps` 检查实际映射。[Docker 端口映射说明](https://docs.docker.com/engine/network/port-publishing/)

Ruri 中显示的 `172.x.x.x` 地址通常是容器地址，手机应填写主机的局域网地址及对外端口。Docker 中的自动发现未必能传到家庭网络，搜索不到时直接填写地址。

**4. 使用服务器授权功能时，提供宿主机标识。** 若需要 Android 在线播放、多人账号或珍藏片段，还需让容器读取这台主机的标识。在 Linux 主机上，确认 `/etc/machine-id` 文件存在且非空，再在 `compose.yaml` 的现有 `volumes` 列表下增加一行：

```yaml
volumes:
  - ruri-data:/data
  - ${RURI_MEDIA_DIR}:/media/library:ro
  - /etc/machine-id:/run/ruri-host/machine-id:ro
```

这是服务 `core` 下的目录列表，保留文件末尾原有的 `volumes: ruri-data:` 定义。不要复制另一台机器的标识。保存后运行 `docker compose up -d`，再到 Ruri 的「服务器授权」激活。

Windows Docker Desktop 用户可在宿主机 PowerShell 中、Compose 文件所在目录执行 `(Get-CimInstance Win32_ComputerSystemProduct).UUID | Set-Content -Encoding ascii ./ruri-host-id`，然后将上例最后一行换成 `./ruri-host-id:/run/ruri-host/machine-id:ro`。容器重建时保留这个文件；换机器时按[授权与换机说明](#服务器授权与账号)重新激活。未提供可用宿主机标识时，管理员仍可使用网页和 WebDAV，授权功能会提示暂不可用。

账号、作品资料、设置和授权保存在 `ruri-data` 数据卷中。**升级时保留数据卷，不运行 `docker compose down -v`**。音视频原文件仍在主机的媒体目录；备份或换机要分别处理应用资料和媒体。

### 首次设置管理员密码

把安装步骤中取得的设置码填入首次设置页面，再输入两遍自己的新密码。设置完成后用 `admin` 和新密码登录；设置码只使用一次，之后不再作为密码。

已有安装继续使用原来的账号和密码。如果忘记密码，按[重置管理员密码](#重置管理员密码)操作。不要为了找回密码删除应用数据目录或 Docker 数据卷。

要修改自己的密码，在「账户与会话 → 修改密码」输入当前密码，再输入两遍新密码。管理员给其他用户创建或重置密码时，也需要输入两遍。

## 升级现有安装

- **Linux**。通过 `install.sh` 安装的服务，在新版本的解压目录再次运行 `sudo ./install.sh` 即可升级。脚本会重启服务，继续使用 `/var/lib/rurimecha` 中的数据。手动启动的安装先停止 Ruri，解压新版后用原来的 `-data-dir` 参数启动。
- **Docker**。在原 Compose 目录的 `.env` 中将 `RURI_IMAGE` 改为发行页上的新镜像，再运行 `docker compose pull core` 和 `docker compose up -d core`。继续使用原有的数据卷与媒体挂载。
- **Windows 客户端**。打开窗口顶部的「Ruri → 检查更新」，确认下载，按提示完成安装。重新打开客户端后会继续使用原来的媒体库。

Ruri 会在启动时自动升级支持的数据库。需要升级数据库时，数据目录下会保存一个名为 `core.db.before-v…` 的备份文件夹。升级完成后，用原账号登录即可继续使用。若启动失败，请保留数据目录，检查空间和写入权限，并根据启动提示核对版本后再重试。

## Windows 卸载

先在系统托盘中选择「退出 Ruri」，再到 Windows 设置的「已安装的应用」中卸载 **Rurimecha**。卸载向导默认保留应用数据，重新安装后可继续使用原来的媒体库。

需要重新开始时，在卸载向导中勾选「同时清除本机 Ruri 应用数据」。这会永久删除 `%LOCALAPPDATA%\Rurimecha\data` 中的账户、媒体库资料、收藏、进度、保存到 Ruri 的台本、设置和本机授权信息；媒体来源目录中的音视频原文件保留。需要保留资料时，请先导出迁移包；需要释放换机授权时，先在「服务器授权」反激活。升级程序不会执行这项清理。

数据目录含有链接或仍被 Ruri 使用时，清理会失败；请先退出 Ruri，并核对数据目录后重试，不要删除链接指向的媒体目录。

## 添加媒体目录

1. 登录管理员账号，在首页点击「添加媒体路径」，选中服务器上存放音声或视频的目录。Windows 桌面版会打开系统文件夹选择窗口；用浏览器连接 Windows 服务器时，可先选择磁盘再打开文件夹，也可以输入 `C:\Music` 这样的完整路径。Docker 用户可选 `/media/library`。
2. 选择需要的自动操作。「自动扫描」查找文件，「自动归档」把文件整理成作品，「自动刮削」为已有 RJ 编号的作品获取资料，「自动提取媒体信息」读取时长、音轨等信息。
3. 添加后，从媒体来源打开目录即可浏览文件。要集中查看整理好的内容，进入作品库。等待期间可在「后台任务」查看进度和结果。

需要调整自动操作时，在目录页打开「目录操作 → 自动处理」。各项可独立开关。关闭自动扫描后仍可手动扫描，已开启的其他操作可以使用已有的扫描结果。归档需要先完整扫描目录，读取时长等信息只需先发现文件。

移除媒体目录会清除该目录在库里的作品、手工整理结果和相关收藏或播放列表条目。原文件留在磁盘上。可以把媒体放在已挂载的硬盘或网络目录，应用数据目录建议放在服务器的本机磁盘。

如果已有 kikoeru 兼容音声库，添加来源时将「来源类型」选为「kikoeru 兼容服务」，填写服务地址。添加后可浏览并选择作品加入自己的媒体库。若要把文件保存到服务器，请填写「服务器下载目录（可选）」后再按需保存。

浏览兼容来源时，右上角搜索用于查找作品；手机上先点搜索图标展开输入框，输入后按键盘搜索键或点搜索按钮。切换到「社团」「标签」或「声优」可浏览该类条目，在页面内的搜索框输入名称可筛选条目；点条目查看对应作品，返回后可继续浏览原列表。

兼容来源的目录和媒体信息在加入作品时取得。需要重新整理作品时，在该来源的目录菜单点「重新归档」；无需另选扫描或提取媒体信息。已设为「普通目录」的文件夹不会因此变回作品；要重新按编号判断，先在该文件夹菜单点「恢复自动判断」。

在目录中将文件夹设为「独立作品」或「普通目录」后，等待重新归档完成，列表会自动更新；未完成时可到「后台任务」查看结果。切换到其他页面再返回目录，会从来源列表开始。目录中的临时搜索和筛选只在本次浏览中保留；需要下次继续使用时，点「保存筛选」。

## 找作品和选版本

在搜索框输入标题、声优、社团或 RJ 编号。输入 `RJ12` 这类编号开头即可找到以它开头的作品。输入至少两个字符并稍等，会显示候选。同一编号存了多份时，可按候选里的来源和目录区分。按回车或点「搜索」查看完整结果。只记得标题时，在「搜索范围」选「仅标题」，作品已保存的各语言标题都可以用来搜索。

作品库中的搜索和筛选在切换到其他页面后清除；作品类型、排序和显示方式继续保留。返回作品库时可重新选择条件。

保存作品资料、语言或版本偏好后，相关显示和筛选立即更新。更改目录的作品归属后会自动重新归档；连续操作会合并处理，可在「后台任务」查看结果。

「有字幕」按最近一次整理结果筛选。在其他软件中添加或删除字幕后，请重新扫描并归档；如果内嵌字幕尚未显示，请获取媒体信息。在 Ruri 中保存或删除台本后，筛选结果会随之更新。

作品卡的标签预览固定两行，可见标签会尽量排满；点「全部标签」查看剩余标签。缺少社团或声优时显示对应图标和“未知社团”或“未知声优”；没有标签时显示“未知标签”和“全部标签（0）”，该占位不可点。作者按声优显示。相同宽度的作品卡保持等高。

已关联的原作和其他语言版本会出现在同一个作品库入口。点「查看其他商品版本」可以分别做以下操作。

1. 在「选择服务器副本」中选中要播放或管理的目录。有多个同号副本时，可按来源和路径区分。
2. 点「服务器播放」收听这份文件，或点「打开服务器文件」查看目录。管理员可通过「打开服务器文件与编辑资料」修改对应作品的资料。
3. 在「商品版本」和「资料语言」中选择要看的资料。比如可以继续听日文原版，同时阅读中文介绍。标为「仅有商品资料」的版本暂时没有服务器文件可播放。

要设定默认播放哪个版本，在账号菜单打开「外观与浏览偏好」，选择「原作优先」或「按版本语言偏好」。想给某一部作品单独指定版本，可在详情页点「设为优先版本」。使用「恢复跟随全局偏好」可以取消单独指定。

通过搜索完整编号、打开具体文件或选择一条收听记录时，Ruri 会打开你选中的内容。查看其他版本的资料也不会切走当前播放。

## 获取和编辑作品资料

### 从 DLsite 获取资料

管理员可在「刮削设置」开启「获取作品资料」，并点击「测试 DLsite 连接」确认可访问。启用后可为带有 DLsite 音声编号（RJ）的作品获取标题、封面和介绍。

### 查看、修改和更新语言

首次安装默认查找简体中文和日文。需要繁体中文或英文时，可以在「刮削设置」选择。可获取哪些语言取决于资料来源。

- 在作品详情的「查看资料」中选择语言，可一起切换标题、介绍、人员、标签、价格和图片等资料。没有的字段会显示为未提供。
- 自己改资料时，在「编辑作品资料」选中要修改的语言后再保存。修改只应用于该语言。
- 资料标为「未知」时，可在「编辑作品资料」打开「未知」并点「设置未知资料的语言」。目标语言已有资料时，选「合并」只补缺少的内容，选「覆盖」会替换该语言整份资料。
- 只更新某种语言时，打开作品的「分项刷新 → 强制刷新商品资料」，选择「本次获取的语言」。其他语言会保留。如有失败，可在任务结果点「重试失败项」。
- 只缺封面或图片时，在「分项刷新」选择补齐图片。该菜单也可用于重新下载图片、获取媒体信息、扫描文件或重新归档。

在电脑上可拖动选择标题、资料、路径或提示，按 Ctrl+C 复制。macOS 使用 Command+C。手机上长按文字即可选择复制。

## 收藏集与播放列表

从作品菜单选择「加入收藏集」，可把整部作品收录到已有或新建的收藏集中。打开收藏集，可像作品库一样浏览封面卡片或切换列表，点击作品查看资料和文件；作品资料更新后，收藏集中也会显示最新内容。

从单个音视频或珍藏片段的菜单加入收藏集时，它会收在这个收藏集的「拾音」中。「拾音」使用作品式封面卡片，打开后可以浏览、播放、加入队列或添加到播放列表。移出收藏只移除收录记录，原文件和原作品归属会保留。

「智能发现」中的合集会随媒体整理结果更新，同样按作品和「拾音」浏览。点击「保存为收藏集」，填写名称并保存，即可得到能自行增删的收藏集。保存时收录的范围会保留，其中作品的资料和内容仍随原作品更新。如果页面提示只收录了部分内容，保存也只包含页面已收录的部分。

需要保留具体曲目、删减范围、重复曲目和播放顺序时，使用播放列表。在当前队列中选择「保存为播放列表」；「收录到收藏集」则收录整部作品和单独添加的音视频。

打开播放列表后，点「播放全部」从头播放；直接点一条音视频会从该条开始，按完整列表顺序继续播放。前面的条目仍可通过「上一首」返回。点「更多播放方式」可随机播放全部、把整表加入队列；搜索后还可选择仅播放搜索结果。直接点搜索结果仍从该条开始播放完整列表。

单条菜单提供「只播放此项」、下一首播放、加入队列、查看文件信息或作品，以及「从这里加入…」，可将该条及后续条目放到下一首或队列末尾。分组标题只用于展开；通过分组菜单播放本组。不可播放的条目不能点播；编辑播放列表不会改变正在播放的队列。

旧版自定义收藏集会在升级后出现在播放列表中，原有编排会保留。曲目过多时会按顺序拆成多个带编号的列表。未保存过具体曲目的作品按升级时的内容展开；无法还原的项目会在列表中显示说明，已保存但暂时找不到的文件显示为不可用。

## 播放与续听

在作品或文件夹里选择音视频播放。同一作品提供多个播放版本或格式时，可在播放前选择，例如带音效版或 WAV。常听内容可以加入队列、播放列表或收藏集。要从上次的位置继续，可从账号菜单打开「收听记录」。

音频播放页、底部播放栏、台本浮窗和本机播放器提供「后退 10 秒」「前进 10 秒」按钮，每点一次跳转 10 秒，也可拖动进度条选择位置。暂停时跳转会保持暂停；未读取到时长或正在加载时，请稍候再操作。

播放音频时，带时间轴的台本会显示当前句。手机竖屏可上下拖动台本顶部的横条，调整封面和台本各自占用的空间；轻点横条可在当前句和多句台本之间切换。横屏可拖动台本侧边的竖条调整宽度，轻点竖条收起台本。

网页版窗口较宽且有足够高度时，开始播放音频会在右下角展开台本浮窗。拖动浮窗顶部横条可调整高度，轻点横条收起；收起后，可点底部播放器的「台本字幕」重新打开。切换作品库、目录或作品详情时，浮窗会保持显示并继续播放。浮窗中可调整台本时间，点曲目可打开同时显示封面和台本的完整播放页。

拖动进度条可以查看目标时间和可用的画面预览。在「播放选项」中可切换字幕、音轨或跳到章节。看不到音轨或章节时，请先为文件获取媒体信息。

在 Android 播放音频时，可打开带时间轴的台本并点击「悬浮字幕」。首次使用时允许 Ruri「显示在其他应用上层」，返回后再点一次。切到其他应用时，字幕会随播放浮在屏幕上。上下拖动字幕可调整位置，点旁边的 × 可关闭。

观看视频时可点「全屏播放」。在网页端按空格暂停或继续，按方向键跳转，按 Esc 退出全屏。Android 可轻点画面显示控件，双击左侧或右侧跳过 10 秒。睡前可以在播放器设置「睡眠定时」。

管理员可从播放器的台本菜单选择「新建台本」或「编辑／转换台本」，并在保存前预览。媒体目录只读时，可选择「保存到 Ruri」。要把台本和音视频放在一起，请选择保存到媒体目录，并确认目录可写。转换格式时请先检查时间和样式。

### 准备音视频工具

Linux、Windows 和 Docker 发行版自带 FFmpeg 和 FFprobe。支持的本地文件可使用兼容转码、音量标准化、画面预览、指定音轨和内嵌字幕；能否使用取决于文件格式和已读取的媒体信息。kikoeru 兼容来源的视频可按可用画质转码播放；其余媒体处理能力以实际可选操作为准。Linux 用户请完整解压发行包，并将 `media-tools` 文件夹与 Ruri 程序放在同一目录。

管理员可在管理页打开「解析工具」查看工具是否可用。若要改用自行安装的工具，请选择支持 `fd` 输入的版本，填写两个程序的完整路径，测试通过后保存。清空两个路径并保存可恢复默认选择。也可在该页联网自动下载工具，服务器需要约 500 MB 可用空间。

### 用其他播放器或文件管理器连接

在支持 WebDAV 的播放器或文件管理器中新建连接，填写：

| 项目 | 填什么 |
| --- | --- |
| 地址 | `http://服务器地址:端口/dav/`；已开启 HTTPS 时改用 `https://证书对应的服务器名称:端口/dav/` |
| 用户名、密码 | 你在 Ruri 中使用的当前账号和密码，不是首次设置码 |
| 路径 | 已在完整地址中填写 `/dav/` 时，不要再重复追加 |

例如服务器是 `192.168.1.20`，对外端口是 `18080`，填写 `http://192.168.1.20:18080/dav/`。通过下文 Nginx 教程连接时可填 `https://ruri.example.com/dav/`。账号要有访问资格；未激活服务器授权时只有内置管理员可用。

连接后可按文件夹浏览并播放原文件，不能上传、删除或改名，也不会把第三方播放器的收听进度同步到 Ruri。新加的文件先在 Ruri 中扫描，之后才会出现在 WebDAV 里。播放格式取决于所用播放器，WebDAV 不转换音视频格式。

**Windows 文件资源管理器怎么添加。** 打开「此电脑」，选择「添加一个网络位置」（有些版本在右键菜单或顶部菜单中），选择自定义位置，输入完整 WebDAV 地址，再填写 Ruri 账号。直接把地址粘贴到浏览器或资源管理器地址栏，不等于已经添加了网络位置。

**HTTP 能在播放器使用，为什么 Windows 却拒绝挂载？** Windows 的 WebClient 组件默认只允许在 HTTPS 下使用账户密码认证。Ruri 的 HTTP 地址可能被它拒绝，表现为反复询问密码、网络名称找不到或错误 67；这不一定是 Ruri 的密码有误。可选做法如下：

- 使用能直接连接 HTTP WebDAV 的播放器或文件管理器，无需修改 Windows 设置。
- 启用 Ruri HTTPS，或按 [Nginx 教程](#通过-nginx-访问-ruri)提供 HTTPS 入口。填写证书包含的名称，并让 Windows 信任证书；不要只忽略浏览器的证书警告后就认为资源管理器也会接受。
- 只在可信家庭网络使用 HTTP、并希望继续使用资源管理器时，可允许 Windows 对 HTTP 发送账户密码。先按 Win+R，输入 `services.msc`，确认 **WebClient** 服务存在。以管理员身份打开 PowerShell，执行：

  ```powershell
  New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Services\WebClient\Parameters' -Name BasicAuthLevel -PropertyType DWord -Value 2 -Force
  Restart-Service WebClient
  ```

  这会对该 Windows 系统的 WebDAV 连接生效，HTTP 连接中的密码没有加密。重启服务会中断已连接的 WebDAV 位置，之后重新连接。以后恢复为仅允许 HTTPS 时，把命令中的 `-Value 2` 改为 `-Value 1` 再执行。若系统没有 WebClient 服务，或设置被单位策略管理，请使用支持 WebDAV 的客户端，不要通过修改 Ruri 密码来反复尝试。[微软说明](https://learn.microsoft.com/en-us/iis/publish/using-webdav/using-the-webdav-redirector)

其他常见情况：

| 现象 | 可以怎么处理 |
| --- | --- |
| 普通网页也打不开 | 先核对服务器地址、Docker 对外端口、防火墙和「局域网范围」 |
| 改密码后仍提示密码错误 | 断开旧网络位置；在 Windows「凭据管理器 → Windows 凭据」中移除这台服务器的旧记录，再用新密码连接 |
| 浏览器打开 `/dav/` 返回“不支持的方法” | 用 WebDAV 客户端添加连接；这个地址用于列文件，不是网页目录页面 |
| 无法复制较大的文件，或报 `0x800700DF` | Windows WebClient 有自己的单文件传输上限，HTTPS 也不会取消这个限制。可改用专用 WebDAV 客户端或播放器；需要调高限制时参考微软说明中的 `FileSizeLimitInBytes` |
| 只在文件特别多的目录中出错 | Windows WebClient 也有目录属性大小上限；优先换用专用客户端，不必为此移动原文件 |
| 能浏览但不能删除、上传或改名 | Ruri WebDAV 只读，这些操作不受支持 |

## 珍藏片段

珍藏片段入口旁的冠饰徽记表示专属权益。请先打开一份可播放且已获取时长的文件；如页面提示权益未开启，联系服务器管理员激活或续期。

1. 在「正在播放」或视频全屏的「播放选项」中点「珍藏片段」。
2. 拖动进度条上的两个手柄选起点和终点。默认选中当前位置之后的 30 秒，靠近末尾时选中最后 30 秒。可点「放大选区」细调。
3. 点「试听选段」，确认后选择「保存片段」。试听到终点会停止，保存或取消后可回到选段前的位置。

在账号菜单点「珍藏片段」可重听，也可从「片段操作」加入队列、播放列表或收藏集，或者调整范围。删除片段也会移除列表里引用的该片段，原音视频仍在。源文件暂时不可用或专属权益到期时，片段保留，恢复文件或续期后可继续使用。

## 在 Android 上收听

打开单独安装的 Android 客户端，选择「搜索局域网服务器」或手动填写服务器地址，然后登录。搜索不到时，检查手机和服务器是否在同一局域网，并确认服务器开启了自动发现。在线播放需要连接有效授权的服务器。

无需先播放媒体：在底部「我的 → 播放设置」切换「手机直连来源」。开启时手机直接连接网络来源；需要使用服务器为来源设置的代理，或手机无法直接播放时，请关闭此项。播放期间也可以从播放详情打开「播放设置」。

### 下载到手机离线收听

1. 在作品详情选择播放版本和格式，点「下载到本机」，勾选要保存的文件。也可从文件菜单下载单个音视频。下载时需登录，且服务器授权有效。
2. 从连接页、登录页或账号菜单打开「本机媒体库」，可查看进度、暂停、继续或取消下载。取消会保留已完成文件。封面或字幕失败时可以重试补齐。
3. 下载完成后，即使没有网络、退出登录或授权过期，也可在「本机媒体库」收听。在线作品详情的「本机版本」也能打开已下载的文件。

下载包含音视频原文件、已有的作品文字、封面和可用的文本字幕。手机需要支持原文件格式。无法播放时，可选择服务器里的其他格式重新下载。默认仅用 Wi-Fi 或有线网络，关闭限制后可能使用移动数据。一次最多下载 500 个文件，本机媒体库最多保留 500 个下载版本。

本机播放支持后台播放、通知控制、循环、随机、睡眠定时、台本和全屏视频。手机里的队列、收藏和进度单独保存。恢复队列后先暂停，可确认内容后再播放。「刷新作品资料」只更新文字、封面和字幕，需连接原服务器、以原账号登录，且服务器授权有效。

删除本机版本只会删除手机上的副本。退出登录或更换服务器会保留下载，卸载应用或清除应用数据会删除本机下载和记录。换手机后需要重新下载作品。珍藏片段可在连接服务器时播放。

## 隐私模式与收听记录

点击主界面或播放器上的眼睛按钮开启「隐私模式」。封面、图片和视频会遮住，标题、标签、文件名和字幕等文字会以星号显示。想确认一处内容时，点遮罩上的小眼睛可查看 3 秒。导航、播放和进度条仍可使用，设置会记在当前设备。

Android 在隐私模式下准备使用扬声器时会先询问，选择「继续播放」后才开始。耳机或蓝牙设备断开时会暂停，重新连接后可手动继续。如果从通知或媒体键发起播放并需要确认，请打开应用。锁屏和通知也会遮住相关文字和封面。

隐私模式下仍会保存收听进度。要清除它，在账号菜单打开「收听记录」，删除单条或点「清空播放记录」。对应的续播位置和完成状态会一起清除。收藏、播放列表、珍藏片段和媒体文件会保留。删除正在播放的记录时，可以继续听完这次播放，重新选择内容播放后会再次记录。

## 服务器授权与账号

未激活或授权到期时，内置管理员仍可登录网页和 WebDAV。要创建其他账号、使用官方 Android 客户端在线播放或使用珍藏片段，请在「服务器授权」填写许可证密钥和服务器名称，点击「激活服务器」。

授权生效后，管理员可在「用户管理」创建账号。用户可以浏览和播放同一个媒体库，各自保存收藏、播放列表、偏好、进度和珍藏片段。可在用户的「访问权限」停用或启用账号。停用会退出该账号的登录并停止它的 WebDAV 访问。密码、角色或授权状态变化后，按提示重新登录。

激活、更新和反激活时服务器需要联网。授权有效期内，Ruri 可以离线使用。续期后可用原密钥更新授权。要换服务器，先在旧服务器反激活，再到新服务器激活。旧服务器无法启动时，联系许可证提供者核对购买信息并释放绑定。替换同一台机器上的 Docker 容器时，请保留数据卷和已配置的宿主机标识。

在「账户与会话 → 登录会话与 WebDAV」可查看当前有效登录的设备名称、客户端类型、登录 IP、登录和到期时间，并撤销不用的登录。IP 记录的是登录时的地址，切换网络后不会更新。浏览器显示浏览器和系统名称；Android 显示设备型号；桌面客户端可显示电脑名称。这里不保存已退出或过期的登录历史。

## 连接与网络

### 从其他设备访问

- **Linux 服务**默认可从同一局域网访问，地址为 `http://服务器的局域网地址:8080/`；无法连接时检查防火墙是否允许该端口。
- **Windows 桌面版**使用安装时选择的监听地址和端口，首次安装默认监听全部 IPv4 地址的 `8080` 端口。要让手机连接，请在 Windows 防火墙中允许安装目录下的 `rurimecha-core.exe` 接收专用网络的入站连接，再使用电脑的局域网地址和所选端口。若安装时只选了 `127.0.0.1`，先在「网络设置」保留本机监听并增加局域网地址。电脑睡眠、关机或退出 Ruri 后，其他设备无法播放。
- **Docker**按照[端口映射和局域网范围步骤](#docker-安装)设置，使用主机地址和对外端口；不使用容器的 `172.x.x.x` 地址。

在「网络设置」的「局域网范围」留空时，Ruri 会自动识别直连的私有网段。需要手动填写时，每行一个网段，例如 `192.168.1.0/24`；Docker、VPN 或跨网段家庭网络可能需要手动补充，填写前保留页面所显示的原有范围。

从局域网外访问时，需要同时开启服务器的「允许远程访问」，以及「用户管理 → 访问权限」中相应账号的远程访问。HTTP 会传输未加密的登录和媒体数据，外网使用 HTTPS 或可信 VPN。经过 Nginx 时，访问范围按[反代教程](#通过-nginx-访问-ruri)处理。

### 开启 HTTPS

在「网络设置」保留 HTTP，或同时开启 HTTPS，并分别设置端口。默认 HTTPS 端口为 `8443`。开启前选择 PEM 格式的证书和匹配的未加密私钥文件；更换时同时选择这两个文件。使用证书包含的名称或 IP 连接，并让设备信任该证书。若当前页面使用 HTTP，请在可信局域网中提交证书文件。

勾选「强制使用 HTTPS」后，HTTP 会跳转到 HTTPS，播放器和 WebDAV 客户端仍应直接填写 HTTPS 地址。修改地址、端口或证书会中断连接，保存前记下新地址，再按提示重新打开。

Docker 还需增加 HTTPS 的端口映射，例如在原有 HTTP 映射下面添加 `"192.168.1.20:8443:8443"`，保存后运行 `docker compose up -d`。需要 HTTP 自动跳转时，HTTPS 两侧端口保持一致，避免被跳到没有映射的端口。通过 Nginx 提供入口时，按下一节设置。

## 通过 Nginx 访问 Ruri

这部分适合已有 Nginx、域名和证书的用户。只想在家里用手机连接时，可以直接使用上一节的局域网地址。

Nginx 可以提供 HTTPS 入口，再通过 HTTP 连接 Ruri；不需要把同一份证书再上传给 Ruri。同机 Nginx 按下面的示例连接时，无需填写「可信代理」，Ruri 使用 Docker 桥接部署时也一样。通过域名登录后，Ruri 按访客 IP 判断局域网及账号远程访问权限。

| 连接方式 | 设置方法 |
| --- | --- |
| HTTPS 入口 → HTTP Ruri | 使用下面的示例，证书只配置在 Nginx 中 |
| HTTP 入口 → HTTP Ruri | 同机连接无需填写可信代理；仅用于可信网络 |
| HTTPS 入口 → HTTPS Ruri | 同机连接无需填写可信代理；另配置上游证书校验 |
| `https://域名/ruri/` 子目录 | 不支持，请使用独立域名的根路径，例如 `https://ruri.example.com/` |

### 示例：同机 Nginx 提供 HTTPS

以下假设 Nginx 和 Ruri 直接运行在同一台 Linux 电脑上，域名为 `ruri.example.com`，家庭网段为 `192.168.1.0/24`。

1. 让域名解析到 Nginx 所在设备，准备与域名匹配、访问设备信任的证书。示例路径为 `/etc/nginx/certs/ruri-fullchain.pem` 和 `/etc/nginx/certs/ruri-key.pem`。
2. 同机 Nginx 无需填写「可信代理」。只通过同机 Nginx 访问时，可在 Ruri 的「网络设置」让 Ruri 仅监听 `127.0.0.1`，HTTP 端口保留 `8080`。若需调整局域网访问范围，在「局域网范围」保留原有网段并加入家庭网段，例如 `192.168.1.0/24`，然后保存。
3. 在 Nginx 的配置目录新建 `ruri.conf`，例如 Debian/Ubuntu 的 `/etc/nginx/conf.d/ruri.conf`，填写：

```nginx
server {
    listen 80;
    server_name ruri.example.com;
    return 308 https://ruri.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name ruri.example.com;
    ssl_certificate     /etc/nginx/certs/ruri-fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/ruri-key.pem;

    client_max_body_size 257m;
    client_body_timeout 600s;
    send_timeout 600s;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header Connection "";

        proxy_buffering off;
        proxy_request_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        proxy_redirect off;
        gzip off;
    }
}
```

4. 将域名和证书路径换成自己的值，检查配置后重新加载：

   ```sh
   sudo nginx -t
   sudo systemctl reload nginx
   ```

5. 用 `https://ruri.example.com/` 登录，保存一次设置，播放并拖动进度。WebDAV 使用 `https://ruri.example.com/dav/`；换机恢复时通过同一入口上传迁移包。

上述示例适用于直接接收用户连接的一层 Nginx。如果前面还有 CDN 或其他代理，须先在 Nginx 中限定并还原这些受信入口的访客地址，不能直接使用用户自填的地址头。可信代理只填自己控制的地址或专用代理网段，不填整个互联网或普通用户共用的网段。

外网访问仍需同时开启 Ruri 的「允许远程访问」和相应账号的远程访问权限。只需家庭使用时保持远程访问关闭，也可在 Nginx 的 HTTPS `server` 中额外添加 `allow 192.168.1.0/24; deny all;`。反代上游跨越不可信网络时，使用 HTTPS 上游或可信隧道。

保留用户原来的认证信息、Cookie、`Origin` 和 `Referer`。不要伪造来源绕过登录检查，也无需另行改写 Cookie。不要另加占用 `Authorization` 的 Nginx 账号密码认证，以免与 Ruri 和 WebDAV 密码冲突。WebDAV 列目录需要 `PROPFIND`，不能只允许 GET/POST。媒体、图片和登录响应不设置公共缓存。

### Docker 与 HTTPS 上游

- **只有 Ruri 在 Docker 中**：使用默认桥接网络并保留 `127.0.0.1:8080:8080` 的端口映射，宿主机 Nginx 连接 `http://127.0.0.1:8080`，无需填写「可信代理」，重建容器后也无需手动更新代理地址。Ruri 的「局域网范围」填写家庭网段。
- **Nginx 和 Ruri 都在 Docker 中**：加入同一个专用 Docker 网络，上游改为 `http://core:8080`；`127.0.0.1` 指 Nginx 容器自身。可信代理填写 Nginx 容器的固定 IP，或该专用代理网络的网段；不要信任其他用户容器共用的网络。Ruri 无须向主机发布端口，访问设备使用 Nginx 的地址。
- **需要 HTTPS 上游**：先在 Ruri 启用 HTTPS，上游改为 `https://127.0.0.1:8443`（容器间为 `https://core:8443`），另加以下设置。`ruri.example.com` 必须包含在 Ruri 上游证书中；家庭自建证书应改填其根证书文件，不关闭校验。

  ```nginx
  proxy_ssl_server_name on;
  proxy_ssl_name ruri.example.com;
  proxy_ssl_verify on;
  proxy_ssl_trusted_certificate /etc/ssl/certs/ca-certificates.crt;
  proxy_ssl_verify_depth 3;
  ```

### 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 登录或保存返回 403 | 访客是否满足局域网及账号访问权限；是否按示例填写代理配置；其他设备或容器中的代理是否填写了可信地址 |
| 反复跳转或跳到 `8443` | 是否按示例填写代理配置；其他设备或容器中的代理是否填写了可信地址；只由 Nginx 提供 HTTPS 时，无需开启 Ruri 的强制跳转 |
| 502 | Ruri 是否运行、端口或容器地址是否正确；使用 HTTPS 上游时再检查证书名称与信任根 |
| 页面能开，播放卡住或不能拖动 | 保留 `Range`，关闭媒体缓存和缓冲，并确认直连 Ruri 能播放 |
| 上传迁移包报 413 | 核对 `client_max_body_size`；Ruri 也有包大小上限 |
| WebDAV 无法列目录 | 使用 `/dav/`；保留认证信息，并允许 `PROPFIND` |


## 换机与恢复

1. 在旧服务器用管理员账号打开「迁移与恢复」。只带走作品资料时，选择「全部作品资料」。要连同账号、设置、收藏和进度一起带走时，选择「系统数据和全部作品资料」。也可只导出系统数据。含系统数据的包需要设置密码，请保存好包和密码。
2. 把媒体硬盘接到新设备，或把文件夹复制到新设备。安装 Ruri 并登录后，打开「迁移与恢复」，选择迁移包，填写新的媒体目录，再点击「预览恢复」。
3. 核对缺失文件后点「恢复」。文件暂时缺失时仍可保留资料、收藏和进度。将文件放回原来的相对位置并重新扫描后，可恢复播放。如果恢复了系统数据，请重启 Ruri，使用迁移前的账号和密码登录。

只搬一部作品时，从详情的「迁移此作品」导出。两台设备上作品在媒体来源中的相对位置相同时，可以从目标作品的同一入口恢复，替换该作品的资料和人工整理结果。目标库还没有该作品时，从「迁移与恢复」导入单部作品包。

包内会保留作品资料、原有资料来源、人工编辑和图片。恢复后，作品仍按原有设置获取更新。音视频原文件、日志、任务记录、服务器授权和手机本机下载需要分别处理。

## 重置管理员密码

- **Linux** 服务安装运行 `sudo /opt/rurimecha/reset-admin-password.sh --service`。如果服务正在运行，脚本会在重置后重新启动。手动启动的安装请先停止 Ruri，在解压目录运行 `./reset-admin-password.sh`，如用了其他数据目录，将目录路径加在命令后，再重新启动 Ruri。
- **Windows** 先从托盘菜单选择「退出 Ruri」，再打开安装目录（默认是 `%LOCALAPPDATA%\Programs\Rurimecha`），双击 `reset-admin-password.cmd`。如使用了其他数据目录，在该安装目录的命令提示符中运行 `reset-admin-password.cmd "数据目录路径"`。完成后重新打开 Ruri。
- **Docker** 在发行版 Compose 文件所在目录运行 `./reset-admin-password.sh`。如果 Ruri 正在运行，脚本会暂时停止它并在重置后重新启动。

使用脚本显示的用户名和新密码登录。用户名和资料会保留，已用这个账号登录的设备需要重新登录。

## 游客体验

管理员打开「用户管理」，开启「游客体验」后，访客可在登录页点「游客体验」浏览和播放作品。游客无法修改作品或保存收藏与收听进度。关闭开关后，游客将无法继续访问；再次开启后可重新进入。公开演示请使用专门的媒体库，并确认作品允许公开播放。

## 选择界面语言

在连接页、登录页或账号菜单点语言按钮，可选择简体中文、繁體中文、日本語、English 或「跟随系统」。登录后也可在「外观与浏览偏好」中修改；该选择随账号保存，其他设备登录后也会使用。未登录时的选择只保存在当前设备；退出账号后恢复该设备的选择。本机媒体库在离线时沿用最近使用的语言。

「跟随系统」优先使用设备支持的语言；繁体中文地区使用繁体，其他中文地区使用简体，没有匹配时使用英语。切换界面语言不会更改作品标题、文件名、收藏名称，也不会改变作品资料、音轨和字幕的语言；这些仍在各自的菜单中选择。

安装程序目前使用简体中文。管理和命令行工具主要使用英语；历史发布说明提供中文和英文。


## 社团、声优和画师

在「社团」「声优」「画师」中搜索名称，点条目查看本库作品；图片使用关联作品的封面。点作品打开详情。在「作品来源」选择 DLsite 分区可发现其他作品，点结果打开 DLsite。也可以点「发现作品」输入尚未收录的名称，或选择已配置的兼容来源查找。按名称搜索可能漏掉作品或包含同名参与者，画师在兼容来源中的结果取决于来源是否支持搜索其署名。点「刷新」从第一页重新获取，失败后保留当前结果，可点「重试」。发现结果不会自动加入媒体库或下载文件。


## 无变化时的自动检查

仅做定期检查且未发现变化时，不会重复归档、获取作品资料或读取媒体信息。已有待办和等待重试的处理仍会继续。

## 查看问题与详细诊断

管理员可在设置中打开「系统日志」，默认查看「需要关注」的问题；切换「全部记录」可查看操作结果，展开详情可查看反馈问题时需要的记录。任务进度、失败项目及重试方法在任务详情中查看。

需要排查问题时，在设置中打开「详细诊断」，开启并保存后重现问题，再关闭并保存。开关对整个服务器生效，重启后保留。关闭后停止新增诊断记录，已有记录仍按容量上限保留；在日志中选择「诊断记录」可查看它们。正常使用时无需开启。


## 收听统计与推荐

从侧边栏或账号菜单打开「收听与推荐」。在「收听统计」查看收听时长、日历、每月趋势和常听作品、声优、社团及标签，可切换最近 30 天、12 个月、年份或全部时间。这里只记录从服务器媒体库播放的内容，手机本机媒体库不计入。

在作品详情点击「我的评分」，选择 1～5 星；再次打开可修改或取消。评分属于自己的账号，针对整部归档作品，不同格式与播放版本共用。卡片上的「我的评分」与作品公开评分分别显示。

「为你推荐」提供「可能喜欢」「换换口味」「久未重听」，点作品查看详情或直接播放，点「换一批」更换推荐。删除续播记录不会删除收听统计或评分。


### 视频画质与转码限制

观看视频时，打开「播放器设置」选择「视频画质」。支持转码的视频可选分辨率和码率档位，切换后会从当前位置继续并重新缓冲；无法转码的视频只显示「原始格式」。本地来源和可读取的 kikoeru 兼容来源视频均可使用。原始格式是否能播放取决于设备。兼容播放的「自动」使用默认画质预算，不会持续随网速升降画质。

管理员可在「解析设置」限制最高转码高度、最大视频转码码率及每个任务的最大工作线程数。分辨率和码率填 0 表示不限；线程数填 0 使用单线程，可指定 1–64。限制对新转码任务生效，原始格式直放不受影响。转码不修改原文件，画面不会放大，保留源帧率。

已结束的任务和运行日志最多保留 48 小时。任务结束后，可查看未完成项并重试；成功项计入汇总。记录过期后，可从作品或来源重新操作。作品资料、收藏、收听进度和字幕草稿不受影响。本次升级不保留旧任务记录；升级成功后不保留旧数据库备份。
