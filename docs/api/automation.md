# 自动监听与定时重扫

所有路径以下省略 `/api/v1`；遵循 [协议约定](protocol.md) 的认证、错误和分页。能力标识为 `library.watch`、`library.schedule`、`organize.incremental`。

通过来源创建接口新添加的路径默认开启自动处理，可通过 automation 对象分别关闭扫描、归纳、刮削和探测四项；已有来源策略保持。普通扫描不读取文件正文。策略按来源持久保存，服务重启后恢复已启用的策略。根目录不再提供停用操作；移除根目录会阻止新任务、自动取消相关任务并清理媒体元数据和自动策略。自动更新开关仍可独立关闭，仅控制是否自动处理，不移除根目录。

## 查询与替换策略

- `GET /sources/{source}/automation`：200，返回 `policy`、字符串 `revision` 和 `status`，携带 ETag。
- `PUT /sources/{source}/automation`：带上 GET 返回的 `If-Match`，请求体为完整 policy，200 返回相同结构。省略的布尔值为 false；这是覆盖而非局部更新。缺少前提返回 428，修订过期返回 412；完全相同的规范化策略不增加修订，也不触发扫描。

例如启用监听、每小时全量核对，并自动归纳：

```json
{
  "watch": true,
  "interval_seconds": 3600,
  "debounce_ms": 1000,
  "reconcile_seconds": 300,
  "auto_scan": true,
  "auto_organize": true,
  "mark_missing": true
}
```

| 字段 | 默认值、范围与语义 |
| --- | --- |
| watch | false；监听目录变动，启用和恢复服务时先全量核对 |
| interval_seconds | 0；0 关闭独立定时扫描，正值 1..31536000 秒 |
| debounce_ms | 1000；省略或 0 采用默认值，允许 20..60000 毫秒；连续事件最长合并 30 秒 |
| reconcile_seconds | 300；省略或 0 采用默认值，允许 1..86400 秒；watch=true 时即使没有事件也定期全量核对 |
| auto_scan | false；独立控制自动扫描，监听和周期仅指定触发方式，不会绕过该开关 |
| auto_organize | false；按持久输入代次自动归纳，覆盖完整扫描、节点属性/决定修改、规则变化和恢复分类。仅启用此项不会扫描目录；已有可信完整索引时可独立工作 |
| mark_missing | false；只有完整成功的扫描才按扫描范围标记消失节点。自动核对删除通常需显式设 true |

同时启用两个周期时，实际全量核对周期取较短值，从全量扫描结束计算；子树重扫不会不断推迟全量兜底。默认 mark_missing=false 保守保留旧 present 节点；若扫描发现未确认的旧记录，归纳可能报 `source_incomplete`，需显式允许缺失核对后重扫。根离线或部分失败，即使 true 也不能推断整个来源被删除。

## 状态与任务衔接

`status` 字段均存在：

| 字段 | 含义 |
| --- | --- |
| effective_revision | 字符串；后台当前采用的策略修订，可能短暂落后于已保存 revision |
| phase | idle / scanning / organizing / processing / settling；本协调器正在执行或等待的阶段 |
| desired_generation / applied_generation | 字符串；来源当前输入代次与已发布代次，独立于策略修订 |
| pending | 有可执行的后续处理、正在运行的任务或待处理变化；仅因关闭某项或缺少输入数据，不会显示为可执行待办 |
| watched_directories | 当前覆盖的目录注册数，可能包含监视根重建所需的父目录 |
| watch_error | 空或降级代码：watch_backend_unavailable、watch_limit、watch_add_failed、watch_index_unavailable、watch_backend_closed、watch_event_error、event_overflow |
| scan_job_id / organize_job_id | 最近由协调器创建的任务 ID，尚无任务时为空字符串 |
| last_error | 最近任务错误或协调器启动错误；正常为空。部分扫描为 scan_partial，归纳可返回已有领域错误代码 |
| next_scan_at / last_finished_at | RFC3339 时间或 null |

状态是后台快照，通常一个调度周期内更新；来源可见性也可能短暂滞后。策略 ETag 仅保护策略编辑，不随状态跳动。扫描和归纳的详细结果、取消及错误沿用现有任务接口；归纳任务的预览/应用结果还返回 `analysis`，详见 [整理接口](organization.md)。

文件事件合并后优先重扫最近可用目录子树，基线不完整时转全量；扫描器忙时保留待处理事件，不创建无限队列。新归纳只从可信完整索引开始；已开始的完整快照允许在输入更新后发布旧代结果。未处理代次持久保存，重启恢复；失败保留 pending 和错误，以最长 32 秒退避重试，取消单次任务不等于关闭策略，仍有未处理输入时，即使没有新事件或周期也会产生新任务。关闭 auto_scan 可停止后续自动扫描，保留监听和周期配置，auto_organize=false 停止后续自动归纳，并请求取消本协调器尚未结束的相应任务；不取消用户单独创建的任务。

监听不是无遗漏事件日志。操作系统不支持、注册上限、队列溢出和新目录尚未注册等情况均靠全量周期兜底；客户端应展示降级状态。网络挂载不保证可靠监听。该策略不提供播放优先级、CPU 配额、磁盘带宽预算或播放期间动态降速。

扫描、归纳、刮削和探测四项自动开关独立；auto_scrape、auto_probe 不要求 auto_organize。新来源省略 automation 对象时四项均开启；提供对象时仅启用明确设为 true 的项目。自动刮削处理已有作品；自动提取处理已索引文件。归档要求已有完整可信索引，并存在可归档媒体、人工根或需要重新核对的作品。刮削只要求已有可用、带受支持商品编号的作品；提取只要求已有文件属性已知的音视频节点，两者不要求来源整体索引完整。缺少相应输入时等待，不创建空自动任务，也不隐式开启扫描。关闭某项会请求取消该项的自动阶段，已提交成功结果保留。

即使自动扫描关闭，监听到的已索引文件写事件仍使媒体观察失效并触发已启用的媒体处理。若实际大小／修改时间已与索引不符，提取会明确失败，需先扫描更新索引，不隐式改写扫描数据。

首次发现文件不启动稳定等待，直接尝试自动提取；已观察到变化的文件单独等待 10 秒。暂缓项在提取阶段完成后即独立安排重试，不等待刮削结束，也不重新归档或刮削。到期重新核对是否可处理；持续写入只更新等待期限，成功结果和失败退避防止同版本反复提取。每个来源最多一个在途稳定重试，批次至少间隔 10 秒；关闭自动提取也会取消此类自动重试。历史任务的暂缓计数不等于当前等待数量。


## 数据依赖与独立执行

- 自动扫描只由自己的开关和监听/定时配置决定。其他开关不会启动或恢复自动扫描。
- 自动归档使用手动或自动扫描留下的完整可信目录记录；不完整记录继续等待完整扫描，不据此撤回已有作品。
- 自动刮削使用已有 active 作品的有效成员与支持的商品编号。作品可来自过去的归档或人工操作，关闭自动归档仍可执行；人工修改商品编号也会重新协调。
- 自动提取使用已索引、可用且大小/修改时间已知的音视频，不要求已归档为作品。没有音视频的目录不会创建自动提取任务。

归档由独立归档任务执行，刮削/提取按可用输入创建 `skip_scan=true, metadata_only=true` 的处理任务；归档失败或等待完整数据不会成为已有资料处理的强制前提。没有任何对应输入的来源，包括已扫描但没有媒体的空来源，不创建后续自动任务。开关和处理确认在重启后恢复；手动创建的任务不受自动开关取消。来源配置在新增时也可以通过 `automation` 独立选择四项，详见 scanning.md。


无变化的全量/子树核对仍完成扫描任务并更新 `last_finished_at`，但不因此推进 `desired_generation` 或新增归档、刮削/提取流程。已有待办、人工输入/规则变化、文件写事件失效以及稳定等待重试继续独立执行，不受此优化抑制。
