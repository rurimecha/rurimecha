# Rurimecha Core 接口对接

当前契约采用节点唯一归属模型。

本目录记录 Rurimecha Core 的公开 HTTP 契约。请使用与服务版本配套的文档和部署者提供的登录凭据。

当前协议路径为 `/api/v1`，仍处开发阶段，允许调整；以与服务版本配套的这份文档为准。协议版本不代表应用版本。先调用 `/info` 检查 `api_version` 与 `capabilities`；不靠解析应用版本号判断功能。

- [协议约定](protocol.md)：认证、跨域、错误、修订、分页和客户端调用流程。
- [作品及元数据](catalog.md)：作品、三语文本、成员、播放组、候选和搜索。
- [固定规则整理](organization.md)：规则配置、预览/应用、目录边界决定、继承/排除、唯一归属和解除、播放分类。
- [扫描](scanning.md)：本地与 kikoeru 兼容来源、作品入库、可选保存、异步任务、节点和失败语义。
- [日志](logs.md)：请求追踪、任务关联及游标查询。
- [OpenAPI 3.0.3](openapi.json)包含公开操作及请求和响应格式，可导入接口工具或生成客户端。请将服务地址替换为实际部署地址。

成功响应直接是资源对象或分页对象，没有统一 data 包装。身份、修订、日志游标均按字符串处理。客户端不能用资源名称或路径推算 ID，不能将 UI 语言当作音轨语言，也不能将网络超时等同于后台任务取消。

最短接入流程：获取部署者提供的管理员凭据 → POST /auth/login 获取会话 → GET /info → POST /sources → POST /scan-jobs → 轮询 GET /scan-jobs/{job} → 分页读取节点 → 创建作品、文本及成员关系。默认扫描不生成作品；可显式归纳，或按来源启用自动归纳策略。详见各篇的请求示例。

- [批量纠正与维护](curation.md)：批量决定、作品根迁移、分页归属差异、恢复自动播放分类及历史清理。
